## 关键退化：所有合法最终选择都是 C

直接回答、重想和始终核验各有 24 次最终选择，全部为 `C`；主动核验的
23 次合法最终选择也全部为 `C`。原始响应中另有重想的中间选择，因此
全部 143 次模型响应为：119 个 `C`、23 个完整 `VERIFY`、1 个截断输出。

| 题目族 | `keep` | `direct` / `rethink` / `always_verify` | `active_verify` |
| --- | ---: | ---: | ---: |
| 严格刷新历史最大值计数 | 3/6 | 各 0/6 | 0/6 |
| 半开区间成员判断 | 3/6 | 各 6/6 | 6/6 |
| 无符号二进制语法 | 3/6 | 各 0/6 | 0/6 |
| 幂等打开/关闭状态 | 3/6 | 各 6/6 | 6/6 |

无反馈、正确反馈、错误反馈三组中，各策略选择通过均为 4/8。
这轮没有观察到合法最终选项随反馈或核验结果变化。
**不能把两类题目全对解释成核验有效**：不用工具的直接回答也同样全对；
另外两类题目则全错。

从结果事后看，这份固定排列里“永远选 C”也会得到 12/24。它是对已记录
选择的描述性对照，不是预注册的新策略、另一次模型运行或独立样本。
目前不能判定这种固定选项退化的原因，也不能由四类题目推断一般能力。

## 成本

下表是各策略 24 条记录的累计实测量，不含共享模型准备/加载；episode 墙钟
包含相应交互、工具执行和本地编排，不能用模型内部 generation 时间替代。

| 策略 | 模型调用 | 工具调用 / 案例 | 输入 / 输出 token | 累计 episode 秒 |
| --- | ---: | ---: | ---: | ---: |
| `keep` | 0 | 0 / 0 | 0 / 0 | 0.002 |
| `direct` | 24 | 0 / 0 | 9,555 / 48 | 4.424 |
| `rethink` | 48 | 0 / 0 | 19,110 / 96 | 8.134 |
| `always_verify` | 24 | 24 / 48 | 11,751 / 48 | 9.460 |
| `active_verify` | 47 | 23 / 46 | 21,296 / 124 | 14.937 |

主动核验没有增加选择通过数，却相较直接回答多用 23 次模型调用、
23 次工具调用，累计 episode 时间约为 3.38 倍；相较始终核验多用 23 次
模型调用、少一次工具调用，累计 episode 时间约为 1.58 倍。
这是本轮顺序执行的观测，不是独立重复的稳定延迟结论。

合计 61,712 个输入 token、316 个输出 token。控制器至最终结果写入前约
71.150 秒；worker 约 69.478 秒，其中加载前准备约 25.203 秒，模型加载约
7.250 秒。PyTorch 峰值 allocated/reserved 为约 15.482/16.029 GiB。
远端预检、事后核验和 SSH 收尾另行执行，不包含在控制器的 71.150 秒内。
峰值整机 RSS、总 CPU/GPU 消耗和能耗未测；allocated/reserved 不等于整卡
显存峰值或隔离保证。

## 结论与下一阶段

本轮完成的是**可靠地执行并验收一次负结果**，不是完成自我改进：
主动核验未提高选择正确率，几乎每次都请求工具，并承担了更高成本。
没有调提示、改排列或追加运行来追求正结果。

在设计下一轮前，需要把验收问题重新收紧：

1. 将恒定 A/B/C 与保留原答案列为事先冻结的对照，并让正确选项位置与题目族
   解耦；不能让固定字母获得偶然高分。
2. 单独验证模型是否会响应**具有判别力的核验事实**，再讨论主动选择何时
   核验；工具执行成功不等于模型有效使用了证据。
3. 保留选择失败、部署回退、修复与误纠正的独立统计，以及完整核验成本。
   采用更多独立题目和独立参考答案审查后，再冻结正式通过门槛。

这些是后续设计要求，不是本轮已实现或获准启动的新实验。原始认证日志、
私有题目裁决材料、运行身份和原始传输证据只保留在本地私有目录，不随分支
发布。本页是脱敏摘要；`benchmark_eligible=false`、
`formal_evaluation_ready=false`、`net_benefit_established=false`、
`isolated=false` 均不变。没有进行 LoRA/SHINE 参数更新。
