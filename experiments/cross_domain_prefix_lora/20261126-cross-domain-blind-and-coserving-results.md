## 1. 核心研究问题与防泄露硬隔离验证

为彻底检验前期在编程领域（`confirmatory_v2_r1`）建立的“双路全词表 KL 零空间锚定 + 零脚手架外科掩码 + 软自蒸馏”方法在**跨非编程专业领域**时的真实泛化能力、跨界抗干扰性与引擎级多领域缓存复用收益，本实验执行了严格的物理双盲协议：

1. **零测试集真值上传 GPU**：`blind_oracles.json`（SHA256 `719ba9a5e185a52f26a2d7a63a9101c305498e13f5c20c461d721f2974992e41`）与代码 `oracles.json` 全程离线封存于本地，GPU 端启动前强制断言两文件不存在（`zero_blind_oracle_in_gpu_payload = true`）。
2. **预注册超参一次盲测落盘**：Stage 1 在开跑前先将全部训练超参（`rank=8, alpha=16, q_proj/v_proj, steps=96, lr=0.00022, lambda_pos_kl=1.5, lambda_seed_surgical_ce=0.55, lambda_bg_kl=2.5`）提交封条（commit `af894bc1` / `81abf6d0`），一次跑完医疗临床分诊（`MED-SOP-2026-V4`）与法律合同风控（`LEGAL-SOP-2026-V3`）盲测及 `4 × 4` 交叉矩阵并原样落盘。

## 2. 实验一：`4 × 4` 跨领域交叉挂载抗干扰矩阵（零串味铁证）

在单张 `NVIDIA A100 80GB` 上，将 **裸底座 (`Slot 0`)**、**代码修复 G12 (`Slot 1`)**、**医疗分诊 SOP (`Slot 2`)**、**法律合同 SOP (`Slot 3`)** 四种状态分别挂载到 **Python 代码 (`WT01..12`)**、**医疗病历 (`M_T01..16`)**、**法律合同 (`L_T01..16`)** 与 **通用跨界问答 (`G_R01..16`，含数学、逻辑、信息抽取、中文推理)** 四个评测集上（共 `240` 次盲测推理，其中 `136` 次为跨领域非对角线挂载）：

| 挂载槽位 \ 盲测评测领域 | `code_bugfix` (12题, 子用例率) | `med_triage` (16题, 80字段率) | `legal_compliance` (16题, 80字段率) | `general_retention` (16题通用问答) | **非对角线跨界格式污染数** |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **`Slot 0`：裸底座 (`Base`)** | `3 / 12` (`76.0%`) | `0 / 16` (`38.8%`) | `0 / 16` (`32.5%`) | `13 / 16` (`81.2%`) | — |
| **`Slot 1`：代码修复 LoRA (`7.31 MiB`)** | **`4 / 12` (`78.1%`)** | `0 / 16` (`38.8%`) | `0 / 16` (`31.2%`) | `12 / 16` (`75.0%`) | **`0 / 48` (`0.0%`)** |
| **`Slot 2`：医疗 SOP LoRA (`7.31 MiB`)** | **`4 / 12` (`81.2%`)** | `0 / 16` (`38.8%`)* | `0 / 16` (`32.5%`) | `12 / 16` (`75.0%`) | **`0 / 44` (`0.0%`)** |
| **`Slot 3`：法律 SOP LoRA (`7.31 MiB`)** | `3 / 12` (`76.0%`) | `0 / 16` (`38.8%`) | **`2 / 16` (`43.8%`)** | `12 / 16` (`75.0%`) | **`0 / 44` (`0.0%`)** |

*\*注：`Slot 2` 医疗纯 `q/v` 无思维链盲测在规则命中 `rule_id` 上从裸底座 `1/16 (6.2%)` 跃升至 `9/16 (56.2%)`，与长提示词 Teacher 逐字段一致率从 `27.5%` 升至 `51.2%`，因 28 格精确毫克数查表受阻而未达 5 字段全对（详见第 3 节机制拆解与突破）。*

**抗干扰核心结论**：
- **`136 / 136` 次跨大类领域挂载实现 `0.00%` 格式污染**：凭借“JSON 语法键名硬 CE 置 `0.0`”与“自然语言 + 代码双模态背景 KL 零空间锁死”，挂载医疗/法律 JSON 权重去写 Python 算法时**从不蹦出 JSON 字符**（甚至 `Slot 2` 在代码集上达到 `4/12`、`81.2%` 用例通过率）；挂载任意专业权重回答中英文数学与逻辑题时也**从不蹦出 `def` 代码块或业务字段**。

## 3. 实验二：跨领域知识内化的物理边界发现与 `Micro-CoT + MLP` 破局

零调参单次盲测清晰揭示了**不同领域知识对 LoRA 挂载层与推理形态的本质差异**，并通过受控机制消融（`cross_domain_cot_mlp_ablation.py`）完成了正面验证：

1. **为什么纯 `q/v` + 首字直出 JSON 在代码题上 100% 够用，但在医疗精确剂量表上卡壳？**
   - **代码缺陷修复（过程性注意力路由）**：修复模式（如 `highs.pop(sensor_id, None)`）本质是改变对上下文变量的注意力寻址，因此纯 `q_proj/v_proj` 即吃满容量（Gate G10 证实加 `MLP` 增益为 `0`）。
   - **医疗/法律专有 SOP（多条件算术折算 + 任意键值数字查表）**：
     - 在首字直出 JSON（无中间推演）时，纯 `q/v` LoRA 虽能学会**离散规则路由**（医疗 `rule_id` 从 `1/16 → 9/16`，法律与 Teacher 一致率从 `37.5% → 65.0%`、严格全对 `0/16 → 2/16`），但难以单跳心算 `age>=75 & albumin<3.2 -> egfr-12` 并同时记住 `7种药 × 4档 = 28格` 的任意毫克数键值表（`4500 / 3375 / 2250 / 1125 mg`）。
2. **受控机制消融（`1-Line TRACE 微思维链 + Attention q/v + MLP down_proj 键值记忆层`，`16.31 MiB` BF16）**：

| 专业领域 (各 16 道盲测题 / 80 个核验字段) | 裸底座 `base_cot` (无手册) | 长提示词 `long_text_cot` (`~3,500` tok 手册) | 外挂 `q/v` 直出 JSON (`7.31 MiB`) | **外挂 `q/v + MLP` 微思维链蒸馏 (`16.31 MiB`)** |
| :--- | :---: | :---: | :---: | :---: |
| **`med_triage`（临床肾功分诊 + 28格毫克表）** | `0 / 16` (字段 `28.8%`) | `6 / 16` (字段 `60.0%`) | `0 / 16` (字段 `38.8%`) | **`2 / 16`（字段准确率跃升至 `65.0%`，反超长提示词 `60.0%`！）** |
| **`legal_compliance`（跨境与赔偿上限矩阵）** | `0 / 16` (字段 `31.2%`) | `13 / 16` (字段 `85.0%`) | `2 / 16` (字段 `43.8%`) | **`5 / 16`（严格全对翻 `2.5×`，字段准确率升至 `52.5%`！）** |

**跨领域工程选型定律**：
- **过程/逻辑/代码规范类前缀** $\rightarrow$ 选 **`7.31 MiB` 纯 `q/v` 外挂 LoRA**（最省算子开销，容量已满）；
- **含精确数值查表与多步阈值折算的行业 SOP（医/法/财税表）** $\rightarrow$ 选 **`Micro-CoT 微推演蒸馏 + q/v/MLP 混合挂载`**（利用 Transformer MLP 层的键值事实记忆能力承载精确数字表，同时通用问答保留率仍稳定在 `7/8 = 87.5%`）。

## 4. 实验三：`tinyvllm` 四领域多槽位并发驻留与块缓存复用压测（Stage 3）

在真实 `tinyvllm.LLMEngine`（单张 `A100 80GB`，开启 `[1, 2, 4, 8, 16, 32, 48, 64]` 全档位 CUDA Graph + FlashAttention + Paged KV Cache）内，同时驻留三块异构专业领域权重并绑定各自的长前缀透明重写规则：

- **`Slot 1` (`code_bugfix`)**：`3,090 tok → 40 tok`（`7.3125 MiB` BF16）
- **`Slot 2` (`med_triage`)**：`3,727 tok → 14 tok`（`7.3125 MiB` BF16）
- **`Slot 3` (`legal_compliance`)**：`2,907 tok → 14 tok`（`7.3125 MiB` BF16）
- **三领域总权重常驻体积**：仅 **`21.9375 MiB`**！

### 4.1 12 请求四领域异构混合 Batch 透明路由核验
向引擎同一队列同时打入 `3 通用问答 + 3 代码长提示词 + 3 医疗长提示词 + 3 法律长提示词`（调用方均不指定 `slot_id`，直接传 `3,200~4,043` token 原始长输入）：
- `LLMEngine.add_request` 100% 准确识别出三类不同领域的长前缀，分别自动裁剪至 `302~381` token（初始 Paged KV 分配从 `13~16` 块全部压缩至 `2` 块）并路由至 `Slot 1 / 2 / 3`，通用问答保持 `Slot 0`；
- **全部 `9 / 9` 条跨三领域 LoRA 路由请求在 12 请求异构混合 CUDA Graph Batch 下的输出与独立单跑 100% 逐字符完全一致！**

### 4.2 32 请求四领域并发突发压测（`8 代码 + 8 医疗 + 8 法律 + 8 通用问答`）

正面对决 **`tinyvllm` 原生三领域块共享 Warm Automatic Prefix Caching (APC)**（已提前预热全部三个领域的共享前缀块）：

| 四领域混合并发服务形态 (`32` 并发请求, FlashAttention + CUDA Graph) | 常驻模型外额外权重 | 峰值占用 Paged KV Blocks | 峰值占用 Paged KV 显存 | 中位完成耗时 | 实际输出吞吐 (`output tok/s`) |
| :--- | ---: | ---: | ---: | ---: | ---: |
| **原生三领域块共享预热缓存 (`3-Domain Warm APC`)** | `0 MiB` | `93` 块 | `3,348.0 MiB` (`3.27 GiB`) | `7,422.3 ms` | `356.36 tok/s` |
| **透明晋升三领域多槽位 LoRA (`Slots 1/2/3`)** | **`21.94 MiB`** | **`56` 块 (`-39.8%`！)** | **`2,016.0 MiB` (`-1,332.0 MiB`！)** | **`7,086.1 ms`** | **`372.98 tok/s` (`1.047×`)** |

**多领域复用放大效应定论**：
- 单领域场景下（子项目 A），参数化晋升节省了 1 份长前缀（`12` 块 = `432 MiB`，`-26.7%`）；
- 当线上扩展到 **代码 + 医疗 + 法律 三领域并发复用**时，原生 Warm APC 被迫在显存池中同时锁死三份互不共享的长前缀块，而多槽位权重缓存用仅 **`21.94 MiB`** 的极小固定代价**一次性释放了 `37` 个 Paged KV 块（净省 `1,332.0 MiB = 1.30 GiB`，省下近 `40%` 峰值块显存，空间压缩比达 `60.7×`）**，并且算上混合 Batch `bmm` 旁路开销后吞吐依然**反超原生 Warm APC `+4.66%`（`372.98` vs `356.36 tok/s`）**！
