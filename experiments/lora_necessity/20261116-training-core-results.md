# 梯度 LoRA 训练核心

日期：2026-11-16。

本阶段在已完成的题库验证之后，补上训练输入和真实 PyTorch 梯度更新核心。
**验证对象是小型合成张量模型，不是真实 Qwen，也不是 LoRA 效果实验。**
没有加载预训练权重、连接远程、重新运行题目或启动模型对照实验。

## 新增能力

- `training_inputs.py`：只读取固定八个监督示例，经既有 tokenizer 测量路径
  形成训练序列。题目提示的 label 全设为 -100；正确答案及 EOS 才参与 loss。
  提示最多 4096 tokens，答案最多 256，训练序列合计可达 4352；
  不截断，也不额外收紧为总长 4096。EOS 后的模板尾部不进入训练。
- `training_worker.py`：在调用方提供的模型 q/v 投影上临时挂载 rank 8、
  alpha 16 的 FP32 LoRA；固定底座参数为 BF16，只把 LoRA 张量交给 AdamW。
  八个示例固定顺序重复两遍，共 16 次更新，没有按结果选 checkpoint。
- 对答案 token 使用正确的前一位置 logit 计算交叉熵。禁用 KV cache、
  dropout 和外层 autocast；检查有限 loss、梯度和参数。
- 对全部底座参数及缓冲区进行前后摘要检查，包含 Qwen 位置编码的
  非持久化 FP32 缓冲区。成功或失败均恢复原投影、训练模式和 RNG 状态。
  意外底座内容变化会报错并要求丢弃模型，不声称能够自动撤销任意模型副作用。
- 返回初始/最终适配器张量，以及逐步 loss、梯度范数、核心分项耗时、
  监督 token 数、适配器和优化器张量字节数。模型加载、保存、启动、
  峰值显存及整条流程成本仍为未知，不写成零。

## 接口与限制

`prepare_training(tokenizer, supervision_raw)` 构造输入；
`validate_training(dataset)` 做严格结构和摘要检查；
`train_adapter(model, dataset)` 返回 `receipt`、`initial_adapter` 和 `adapter`。
调用方负责加载和核验模型、运行环境准入及适配器持久化；当前没有启动 CLI。
训练完后底座恢复为没有适配器的模型，训练出的适配器作为独立张量返回。

输出标记为 `LORA_TRAINING_CORE_RESULT_UNATTESTED`。输入/输出摘要可以发现
内容变化，不能证明是谁产生了内容、模型 checkpoint 来源或远程运行真实性。
CPU 路径用于小张量测试；真实 Qwen 必须走之后单独验收的远程路径。

## 已做验证

本地环境为 Python 3.12、已有 PyTorch 2.12.0，无新增依赖。

- 输入构造：25 项新测试通过，另有 19 项既有 tokenizer 测量测试通过。
- 训练核心：最终 17 项新测试通过，使用真实 autograd 和 AdamW，不是假优化器。
- 覆盖初始零增量、第一步 A/B 梯度差异、答案位置对齐、16 步更新、
  底座不变、重复运行一致性、失败恢复、非法结构/精度、非有限输出、
  优化器参数越界和耗时/字节数一致性。
- 测试先观察了缺失实现的失败。另一个真实回归暴露了外层 autocast 会改变
  适配器运算精度的问题，补充启动前拒绝后通过。
- 输入到张量核心的串联检查通过：合成 tokenizer 处理八份固定监督材料，
  小张量模型完成 16 步、80 个监督 token。没有调用真实 tokenizer 或模型。
- 首轮全目录回归共 499 项：497 项通过，2 项平台跳过，耗时 73.900 秒；
  这是下述审查修复前的历史记录。
- 修复后全目录回归共 **502 项：500 项通过，2 项平台跳过**，耗时 74.031 秒。
  使用 tuple 默认配置的输入到张量核心串联检查也再次通过。
- 既有封存的 250 个私有证据文件和 51 个工作区文件摘要全部保持不变。

这些测试不计入此前 1416 项远程题库观察，也不是新增的模型成功样本。

## 独立审查

首轮审查接受了输入结构和 loss 对齐，但复现了两个需修复的问题：
异常退出跳过底座摘要检查，以及没有显式要求结构化模型输出时的 tuple
兼容性问题。新增三个回归分别先复现失败，再修复：

- 恢复原模块、参数标志和模式之后，无论成功或异常都核验底座；底座改变或
  无法核验时，明确要求丢弃模型，保留原始异常作为原因。底座不变时仍抛出
  原来的异常，不伪造成功回执，也不声称已经撤销底座内容变化。
- 前向显式传入 `return_dict=True`，不修改调用者的配置。

独立复审已关闭这两个问题，对本阶段代码给出 Spec PASS / Quality APPROVE，
没有新增需修复项；随后主端完成上述 502 项回归和修复后串联检查。
审查接受的是训练核心代码，不是真实模型/远程运行准入。
