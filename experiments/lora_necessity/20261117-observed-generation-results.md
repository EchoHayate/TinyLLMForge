# 生成观察封装：组件验证

日期：2026-11-17。

本阶段新增 `observed_generation.py`，保留原 `generation_core.py` 的生成规则。
调用前独占保存尝试记录，观察模型根节点的 forward hooks，成功时保存原样
生成记录及独立观察记录，失败时保留已观察到的工作和原因。不重试、不执行
输出、不训练，也不将未知输出 token 数填写成零。

## 已验证

- 独占 claim、消息快照、tokenizer/候选摘要与计数绑定、hook 生命周期。
- 中途 forward、解码、hook 安装/移除、写入和发布失败的原因与证据。
- 修复独立审查发现的终态矛盾：完成观察记录发布成功后，临时名字清理失败
  不再把已提交成功改成失败。清理问题通过独立 `record_cleanup` 返回。
- 发布前的写入/link 失败仍然中止；后续清理错误不覆盖主要失败。
- 失败计数明确为根节点 hook 的观察次数，不是普遍精确的函数体或 kernel
  完成数。全局后置 hook 可在函数体返回后、观察后置 hook 之前抛错。

## 测试与审查

- 33 项观察封装测试通过；与原生成组件合计 57 项通过，无跳过。
- 全量回归最初发现三处合成 Torch 测试污染父进程，导致后续 tokenizer
  冷启动检查失败。已将这三项测试移到独立子进程，保留实际模型/hook 断言，
  不修改冷启动守卫。完整观察测试后再做冷启动/session 检查，35 项通过。
- 最终全量：707 项，705 项通过、2 项跳过，213.233 秒，退出码 0。
  上述专项测试包含在全量或彼此重叠，不能将它们相加当作独立样本量。
- 独立组件复审接受发布边界修复；主协调者核对后续测试隔离改动和全量结果。

## 边界

组件通过不代表真实任务纠错有效，也不代表 LoRA 优于文本记忆。
硬杀后可能只有 claim 或 generation，没有终态观察；这种尝试仍是不完整，
不能据此重试或当作零成本。观察耗时不包括其自身记录发布/清理，不能作为
完整流程总成本。真实底座生成、任务执行和最终评分分别验收。
