## 文档核实与设计含义

| 官方资料说明 | 对本任务的含义 |
| --- | --- |
| 正值 `--memory-swap` 与 `--memory` 相等时禁止容器使用 swap | 候选配置应同时明确两项；不使用“只限制内存”的含糊配置 |
| tmpfs 大小可配置，内容可能进入 swap，容器停止后数据不保留 | 有空间限制候选机制；仍需无 swap 验证和停止前的有界结果回收 |
| `--read-only` 与可写 volume 可同时使用 | 必须核对所有可写挂载，不能只看根文件系统的只读标记 |
| v24 run 文档列出 `/dev/shm` 默认大小 64m | 辅助挂载不能遗漏；需禁写或计入总预算，不能额外白送一份空间 |
| `--log-driver=none` 禁用容器日志驱动记录 | 可避免该驱动另存一份任务 stdout/stderr；不等于关闭所有宿主服务日志 |
| `--stop-timeout` 是发送停止信号后的等待时间；`--rm` 在退出后清理 | 两者均不能代替任务总时限及断连后的自主清理机制 |
| `--pull=never` 在镜像不存在时失败，不隐式下载 | 候选后端必须使用获准的本地固定镜像，缺失即停，不现场自动拉取 |

这是对文档的归纳及本任务的设计推论。尚未核实宿主内核、daemon、
挂载组合和精确运行环境能否共同满足全部要求。

## 路线比较

1. **推荐：专属 Docker 任务加最小远端生命周期控制。**
   利用已观察到的服务能力，目标是为这一次受信 CPU 审计建立资源域、
   有界存储、到期停止和独占清理，不做通用调度平台。
   缺口是准确镜像、所有写入路径及独立于 SSH 的生命周期控制，
   因此不是一条现成可运行的 `docker run` 命令。
2. **平台已有的托管任务或专属资源组。**
   如果平台能提供满足相同边界的资源与租期机制，可减少自建控制逻辑。
   目前没有该接口和授权的证据；不能假定其存在或切换到其他服务器。
3. **宿主普通进程加单进程限制。**
   不采用。当前规格要求聚合限制和完整任务清理，
   已检查路径没有提供专属资源组的可写权限证据；
   不能用单进程限额或定时查看用量替代。

## 推荐路线的待认可设计边界

### 一次性资源域

本次审计及属于本次的准备、写入、采集辅助任务都要明确归属，
不能把 helper 放在预算外再声称全部任务已受限。
4 GiB 聚合内存、8 个进程/线程任务、禁用 core dump，
以实际资源组和行为证据验证，不仅检查提交给 daemon 的配置。
平台既有控制面与本次新增任务的边界要列明；Docker 的单容器参数
不自动约束宿主 SSH 或宿主控制程序。

### 整体存储预算

优先考虑只读运行环境配合显式限容的临时存储；
每个允许写入的目的地都必须有归属及预算。
单一空间域或多个硬限额之和应不超过 128 MiB，
快照、输入、结果、日志、临时及辅助存储不得遗漏或重复冒充共用配额。
结果、两路日志继续各自受限；进程缓存及临时目录不能落入无界宿主路径。
未明确镜像自带 volume、辅助挂载、输出副本或控制端接收根的处理前，
不把“一个 128 MiB tmpfs”标为全链路存储验收通过。

### 独立生命周期与结果路径

控制端负责绑定本次输入、接收有限输出和验证证据；
远端控制负责连接断开后仍能到期停止，只能处理准确归属本次的对象。
禁止自动重启和自动重试，不向审计进程暴露 Docker socket、凭据或 agent。
从初次连接开始的 600 秒总窗、540 秒工作窗与清理剩余窗不重置；
本地与远端期限的映射须保守验证，不能从容器启动时重新获得 600 秒。

正常路径先传回并核验有界结果，再确认任务、后代、传输及临时存储释放。
异常路径宁可留下本地失败回执，也不延长预算去抢救结果。
清理没有完成证据就记为 `CLEANUP_UNVERIFIED`，不自动开始下一次任务。
不能把发送 kill、SSH 退出或容器退出的单一事件当成完整释放证明。

### 验收先于 tokenizer

先设计独立、有限的小型行为探针：跨子进程的内存归属、任务数上限、
跨目录合计占用、单项结果/日志上限、禁止额外写路径，以及超时、
断连、输出回收失败后的归属和清理。探针自身须在已定义的外层边界内，
不得用无界 fork 或内存耗尽来验证尚未生效的限制。
小限额探针不等于最终 4 GiB/8 任务/128 MiB 配置已验收；
真实配置还需单独绑定与验证。

通过后才另行冻结准确 runtime、只读快照及私有投影传输范围，
再运行真实 tokenizer。不能把这里的设计或后端验收当成 LoRA 收益证据。
