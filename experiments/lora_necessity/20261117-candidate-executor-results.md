# 候选执行器：组件及远端固定样例结果

日期：2026-11-17，Asia/Shanghai。

**已实现请求/收据协议、外部进程控制端、隔离内 worker 和保守语法准入 v2。
91 项专项测试通过；完整回归 674 项中 672 通过、2 跳过。
原远端 17 个固定样例通过；随后独立批次的 10 个准入/生命周期样例也通过。**

本报告没有模型效果分数，没有重新训练或执行模型生成的候选。
这是执行器工程验收，不是 LoRA 优于文本记忆或 RSI 成立的证据。

## 实现

- `candidate_execution_protocol.py`：校验现有请求身份和格式，发送内容仅含
  源码、入口与参数；严格解析结果，由控制端观察生成收据。
- `candidate_execution_controller.py`：独占单次 claim，收到就绪消息后才发送
  输入；非阻塞读写、有界输出、截止时间、进程终止与回收均在候选外完成。
- `candidate_execution_worker.py`：隔离初始化完成后接收一个用例，
  调用函数并提供结果；不持有评分答案，不自行判断 pass/mismatch。
- `candidate_execution_admission.py`：逐节点、逐作用域检查允许的计算语法，
  将完整请求摘要与政策版本独立保存，再进入控制端。

候选打印的请求摘要、status 或 pass 不作为控制数据。
已有 `candidate_feedback.py` 继续负责与公开 expected 比较，不修改评分规则。
这些新增组件不读隐藏评分文件、不加载模型、不连接推理引擎主路径。

## 修复及审查

测试真实复现了共享 JSON 编码函数被替换后，将函数返回的 7 伪装成 999。
独立审查又指出修改 `builtins.bytes`、`ValueError`、`type` 的相关路径。
实现改为在候选执行前保留 C 编码器、输出构造器、异常身份，
并让返回值检查使用独立内置函数字典；相应固定篡改样例均通过回归。
这不证明任意 native 内存写入或解释器内部 frame 篡改不可行。

其他已复现修复：

- 输入参数不再误用返回结果的节点数限制；
- 候选计时从第一次尝试发送输入开始，不提前消耗在 READY 后的调度间隔；
- 回收失败不获得第二次完整等待预算；
- 协议与 worker 对默认参数、注解的拒绝规则一致；
- 超大结果最多输出真实 JSON 的前 16385 字节，控制端据实判 output_limit。

初次审查的不通过记录和 RED 日志均保留；修复后的组件复审通过。
远端脚本初审指出外层超时可能打断记录保存，保留未执行的 V1，
另建 V2：25 秒内部截止时间，启动新用例前至少留 6 秒，
本次诊断每用例初始化 2 秒、运行至多 1 秒、回收 2 秒，
并保留记录时间。专门的截止时间样例使用 0.2 秒。
三项该策略测试先 RED 后 GREEN；V2 独立启动前审查通过。
没有修改系统调用允许列表，没有自动重试。

## 远端实测

所有样例使用手写 toy 函数，不使用冻结任务、参考答案或模型输出。
每个新子进程都先完整通过 V3 的 17 项隔离检查，再接收源码。

| 样例 | 实际结果 |
| --- | --- |
| 正常返回、ValueError | completed，值或异常类型正确 |
| RuntimeError、无结果退出 | program_error |
| stdout 打印伪造状态 | completed，仍采用真实函数返回值 |
| 返回长得像收据的字典 | completed，字典仅作为普通返回值 |
| stdout、stderr、结果管道超限 | output_limit，各一例 |
| 死循环 | timeout，已回收 |
| 额外伪造结果再正常返回 | program_error，不接受多条结果 |
| JSON 编码函数、bytes 篡改 | completed，保留真实返回值 |
| 异常类型、type 篡改 | program_error，未伪装为合法结果 |
| 前一用例写临时文件、下一用例检查 | 两例均符合预期，下一用例看不到前一文件 |

共 17/17 个预定样例。远端回执记录完整输入、退出状态、回收状态、
原始有界输出摘要；本地从原始流重新构造收据，并逐一比较预定结果，
不只相信样例自报的通过标记。

单次 SSH 启动到退出约 12.284 秒，包含连接及其他外层开销，
不作为候选性能或推理时延指标。实际用例控制端墙钟约 0.197–0.502 秒，
包含隔离初始化与退出；0.2 秒截止时间不等于整个用例墙钟。

## 准入 v2 与补充实测

独立原始证据审查指出：任意 Python 仍可能只写一条伪造结果，再正常退出。
因此不能仅凭原有 17 个样例就允许模型生成代码进入低层 worker。
新增语法准入保留原文和 Python 语义，拒绝反射、导入、动态执行、
非允许属性及间接调用。拒绝表示整个当前协议不能继续，不算模型答错，
不产生纠错反馈，也不能换个答案免费重试。

初版检查把推导式目标错误地当作函数外层绑定，可能暴露被禁止的内置函数。
审查的 P0 已通过纯静态准入测试复现，没有执行其 payload。
v2 按函数/推导式作用域解析名称，最外层 iterable 使用外层作用域；
内置调用名及入口名禁止在任何作用域重新绑定。另补充精确 JSON 类型预检、
短写检测、独占 0600 准入记录、请求快照与收据摘要绑定。
修复后 25 项准入测试通过，独立复审关闭原 P0，无剩余具体 P0–P2 项。

新远端批次使用独立目录和 claim，没有重跑原 17 个样例：

| 新样例 | 结果 |
| --- | --- |
| 经准入的正常返回 / ValueError | 两例 completed |
| 经准入的死循环 / 大结果 | timeout / output_limit |
| 单结果伪造路径 / 推导式绕过 / 内置名别名 | 三例启动前拒绝，无执行文件 |
| 低层先写结果，再继续运行 | timeout |
| 低层先写结果，再持续输出 | output_limit |
| 低层先写结果，再显式退出 9 | program_error，退出码确为 9 |

总计 7 个执行、3 个拒绝。每个执行子进程先通过原 V3 的 17 项检查。
三个低层样例均实际观察到完整的提前结果帧，不能只凭最终错误状态算通过。
拒绝样例只有空目录，没有准入记录、进程 claim、输出或执行收据。
这些低层诊断具有真实候选不允许的能力，仅用于验证控制端，不代表允许候选使用。

新批次连接总墙钟 4.673277 秒，正常退出并带身份、末尾完成标记。
本地从原始流重建收据，核对完整 child argv、请求及 payload 摘要、
实际声明的超时/输出限制、保存记录和预定结果。
源码导入使用先核对 SHA256 的字节快照。此前 V1/V2 原始产物保留不变。
独立原始记录复核也确认了 7 次执行、3 次拒绝及全部 33 个来源固定项，
没有发现差异；174 个受保护文件的逐项哈希由主流程核对，不冒称审查者重复核验。

## 验证和边界

- 协议 29 项、控制端 20 项、worker 17 项、准入 25 项，共 91 项通过。
- 最新完整回归正常退出：674 项、2 跳过，222.783 秒。
- 先前 66 项专项、649 项完整回归及其失败中间记录保留，未覆盖。
- 本地固定辅助程序和 toy 函数测试不等于执行模型候选。
- 174 个此前实验及隔离阶段文件摘要保持一致，旧失败没有覆盖。
- 内部路径、连接命令和原始回执仅在私有阶段目录保留。
- 工作仍在 `experiments/feedback-active-verification`，没有提交或推送。

固定样例与准入复审通过不等于接受任意 Python 候选：
结果通道仍来自候选所在解释器，不是不可篡改的认证通道。
`candidate_execution_admitted` 和整体效果/收益标志仍为 false。
保守准入实现与固定执行接入已经推进；远端随机小模型的版本兼容另见
`20261117-remote-generation-compatibility-results.md`。
后续仍需真实底座生成、两轮流程及失败/成本绑定，再运行原定四道开发题；
不得把缺少评测的状态写成 LoRA 没有效果或已有效果。
