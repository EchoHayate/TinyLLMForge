# Adaptive N-Gram Source-Auditable Manifest Design

Date: 2026-07-17

## Objective

Make the adaptive n-gram remote gate produce canonical evidence for an
uncommitted K1 fast path without committing that path before GPU validation.

This design uses **SAM** to mean **Source-Auditable Manifest**. It is unrelated
to the suffix automaton draft source also present in this repository.

The gate must prove all of the following from downloaded artifacts:

1. The exact source bytes executed remotely are identified by path and
   SHA-256, not only by `HEAD` and a dirty flag.
2. A saved `source.patch` plus the recorded base commit reconstructs those
   bytes for every tracked owned file.
3. The remote source snapshot matches the locally approved snapshot before
   any model process starts.
4. The K1 dependency-light regression test runs against that same remote
   snapshot and proves `query_len == 0`, no tail prepare/forward, and no CUDA
   synchronization calls.
5. Existing raw-row, summary, report, correctness, repetition, and performance
   gates remain independently recomputable.
6. Artifact verification fails closed for a changed source file, patch,
   manifest hash, base commit, missing test record, or failed remote test.

The first phase changes evidence and orchestration only. It does not change
the adaptive policy, prompt bank, thresholds, profiler semantics, or the K1
fast-path implementation under measurement.

## Current Evidence Gap

`tools/run_adaptive_ngram_gate_remote.sh` currently:

- records `git rev-parse HEAD`;
- records whether any worktree path is dirty;
- sends the current `tools/profile_ngram_commit.py` bytes to an isolated
  remote directory;
- runs the adaptive gate and downloads its result.

This is insufficient for an uncommitted performance candidate:

- `source_commit + source_dirty=true` does not identify the dirty bytes;
- the artifact contains neither a patch nor per-file source hashes;
- `tools/test_ngram_speculative.py` is not uploaded or executed remotely;
- the local verifier recomputes result tables but cannot prove which K1
  implementation produced them.

A canonical result from the current runner could therefore be correct as a
measurement but not reproducible or attributable as evidence.

## Alternatives Considered

### 1. Recommended: Self-Contained Source-Auditable Artifacts

Create an owned-source snapshot before upload. Record every regular file's
relative path, size, and SHA-256; save the tracked dirty delta as
`source.patch`; execute and archive the exact snapshot; then reconstruct it
from the recorded commit and patch during local verification.

Advantages:

- allows the K1 candidate to remain uncommitted until GPU validation;
- artifacts remain auditable after the worktree changes;
- detects transfer corruption and post-run artifact tampering;
- keeps the existing isolated remote execution model;
- narrows trust to Git object identity, patch bytes, and cryptographic hashes.

Costs:

- duplicates the small source snapshot in the artifact directory;
- requires a temporary Git reconstruction during local verification;
- adds one source-evidence schema and several fail-closed checks.

### 2. Commit Before Measurement

Commit the K1 fast path, record the clean commit, and keep the current runner.

This is simpler, but violates the explicit requirement not to commit or
promote the K1 change before real remote validation. It also weakens the
development gate by making validation and acceptance the same action.

### 3. Record Only the Dirty Patch

Save `git diff` and its hash while retaining the current upload behavior.

This identifies the textual delta but does not independently prove the remote
files equal `base commit + patch`. It also misses transfer corruption,
accidental extra files, and a patch that does not cover all executed source.

## Decision

Implement Alternative 1.

The canonical artifact is valid only when all three source views agree:

1. the local approved worktree snapshot;
2. the remote preflight and execution snapshot;
3. the downloaded artifact snapshot reconstructed from base commit plus
   `source.patch`.

Any disagreement classifies the gate as `INCOMPLETE`; it is never interpreted
as a performance `NO_GO` or correctness `NO_GO`.

## Owned Source Boundary

The source evidence covers exactly the files that can influence this gate or
its audit:

- every regular file under `tinyvllm/`;
- `tools/draft_model_schema.py`;
- `tools/profile_ngram_commit.py`;
- `tools/adaptive_ngram_gate.py`;
- `tools/test_ngram_speculative.py`;
- `tools/test_adaptive_ngram_gate.py`;
- `tools/run_adaptive_ngram_gate_remote.sh`.

Directory expansion is deterministic:

- paths are repository-relative POSIX paths;
- only regular files are included;
- traversal is lexicographically sorted;
- symlinks, sockets, generated bytecode, caches, experiment outputs, and
  unlisted tool files are excluded;
- a missing required path or an untracked file inside the owned boundary is
  an error.

The remote execution payload uses the same source snapshot. Files used only
for local orchestration or audit may be present without being executed.

## Source Evidence Schema

The runner creates `source_evidence.json` before any network transfer:

```json
{
  "schema_version": 1,
  "base_commit": "<40-hex commit>",
  "dirty": true,
  "patch_path": "source.patch",
  "patch_sha256": "<64-hex sha256>",
  "patch_size_bytes": 1234,
  "owned_roots": [
    "tinyvllm",
    "tools/draft_model_schema.py",
    "tools/profile_ngram_commit.py",
    "tools/adaptive_ngram_gate.py",
    "tools/test_ngram_speculative.py",
    "tools/test_adaptive_ngram_gate.py",
    "tools/run_adaptive_ngram_gate_remote.sh"
  ],
  "files": [
    {
      "path": "tinyvllm/__init__.py",
      "size_bytes": 0,
      "sha256": "<64-hex sha256>"
    }
  ],
  "tree_sha256": "<canonical-json sha256>"
}
```

`tree_sha256` hashes only the sorted `files` records using compact,
key-sorted UTF-8 JSON. Timestamps, absolute paths, hostnames, and run tags are
excluded so that the identity is stable.

`source.patch` is generated with:

```bash
git diff --binary --no-ext-diff <base_commit> -- <owned paths>
```

The patch is an artifact even when clean; a clean snapshot has an empty patch
whose SHA-256 is the standard empty-file digest. Untracked owned files are
rejected rather than encoded separately because the current K1 candidate uses
tracked files only and a second reconstruction format is unnecessary.

## Snapshot and Transfer Flow

### Local Snapshot

Before SSH:

1. Resolve the full 40-character `HEAD`.
2. Reject staged, unstaged, or untracked changes outside the owned boundary.
   This prevents an apparently canonical run from silently ignoring unrelated
   source state.
3. Expand and hash the owned files.
4. Generate `source.patch`.
5. Verify in a temporary directory that `git archive <base_commit>` followed
   by `git apply --binary source.patch` reproduces every owned file hash and
   no unexpected owned path.
6. Write the evidence and exact source bytes to a run-local staging directory.

The existing two K1 dirty files are permitted because they are inside the
owned boundary. The staging directory must live under a run-local `mktemp -d`
path and is removed by a shell trap.

### Remote Preflight

The runner uploads the staging directory, not a second read of the mutable
worktree. On the remote host:

1. Recompute all source file hashes from the uploaded snapshot.
2. Recompute `tree_sha256`, patch SHA-256, and patch size.
3. Compare them with `source_evidence.json`.
4. Run `py_compile` and both `--help` checks.
5. Run:

   ```bash
   PYTHONDONTWRITEBYTECODE=1 PYTHONPATH="${REMOTE_DIR}" \
     "${REMOTE_PYTHON}" tools/test_ngram_speculative.py
   ```

6. Save a structured `source_preflight.json` containing the source tree
   identity, command, return code, and test output hashes.

No model process may start unless source verification and the K1 regression
test both pass.

### Gate Execution

`tools/adaptive_ngram_gate.py run` receives the verified source-evidence and
preflight paths. It:

- embeds the complete source-evidence object in `manifest.json`;
- embeds the structured preflight record in `manifest.json`;
- refuses to run if either record is invalid;
- copies `source.patch`, `source_evidence.json`,
  `source_preflight.json`, and the exact owned source tree to
  `artifacts/source/`;
- stamps every normalized row with `source_tree_sha256` in addition to the
  base commit and dirty flag.

Resume compares source tree identity, patch identity, and preflight test
identity. A run cannot resume with a different dirty implementation even when
the base commit and run tag are unchanged.

### Downloaded Verification

`verify_artifacts()` performs the existing raw-row, summary, and report
recomputation, then additionally:

1. validates source-evidence and preflight schemas;
2. hashes every file under `artifacts/source/`;
3. rejects missing, extra, changed, non-regular, or duplicate paths;
4. validates `source.patch` size and SHA-256;
5. checks every raw row uses the manifest's source tree identity;
6. requires the remote K1 test return code to be zero;
7. creates a temporary checkout from `base_commit`;
8. applies `source.patch` with `git apply --binary`;
9. verifies the reconstructed owned tree equals the artifact source tree.

The last two steps require verification from a repository containing the
recorded commit. If that commit is unavailable, verification returns an
explicit source-evidence error rather than trusting artifact hashes alone.

## Components

### `tools/adaptive_ngram_gate.py`

Add focused source-evidence helpers:

- deterministic owned-path expansion;
- file and tree hashing;
- evidence construction and validation;
- patch validation;
- base-commit-plus-patch reconstruction;
- artifact source materialization;
- remote preflight record validation.

Add CLI commands:

- `snapshot-source --repo-root --out-dir`;
- `verify-source --source-root --evidence --patch`;
- existing `run` gains `--source-evidence`, `--source-patch`, and
  `--source-preflight`;
- existing `verify` performs full source reconstruction by default.

The helpers use only the Python standard library and Git subprocesses.

### `tools/run_adaptive_ngram_gate_remote.sh`

The runner:

- restricts dirty-state checks to the explicit owned boundary while rejecting
  changes elsewhere;
- creates one run-local staging directory;
- calls `snapshot-source`;
- uploads only staged bytes;
- invokes remote `verify-source`;
- runs and records the K1 unit test;
- starts model work only after preflight passes;
- pulls self-contained artifacts;
- runs the local full verifier against the downloaded artifacts.

It continues to use `sitian@10.232.195.203`, the configured remote Python,
an isolated remote run directory, and distinct dynamic
`TINYVLLM_DIST_PORT`/`MASTER_PORT` values for every model process.

### `tools/test_adaptive_ngram_gate.py`

Dependency-light tests cover:

- deterministic file ordering and tree identity;
- dirty patch reconstruction from a temporary Git repository;
- clean empty-patch reconstruction;
- rejection of untracked, missing, extra, and changed owned files;
- rejection of patch hash and tree hash tampering;
- manifest and resume source-identity mismatch;
- failed or missing remote K1 preflight;
- raw row source-tree mismatch;
- downloaded artifact source tampering;
- successful complete artifact verification.

Existing gate decision tests remain unchanged except for synthetic source
evidence required by the strengthened manifest.

### `tools/test_ngram_speculative.py`

The existing dirty K1 regression remains the normative behavioral check:

- accepted tokens are `[4]`;
- `query_len == 0`;
- target spec-verify calls are zero;
- tail prepare calls are empty;
- CUDA synchronization calls are empty.

No additional K1 behavior is introduced by this evidence work.

## Failure Classification

These conditions are `INCOMPLETE`:

- source snapshot creation or reconstruction failure;
- dirty path outside the owned boundary;
- untracked owned file;
- local, remote, manifest, row, or artifact source hash mismatch;
- patch missing, changed, incomplete, or not applicable;
- base commit unavailable;
- K1 remote test missing or nonzero;
- resume source identity mismatch;
- transfer or artifact source corruption.

Existing semantic output mismatch remains `NO_GO`. Existing complete
performance-threshold failure remains `NO_GO`. Evidence failures must not be
collapsed into those product decisions.

## Validation Sequence

### Local Red/Green

Run after each TDD slice:

```bash

PYTHONDONTWRITEBYTECODE=1 python3 tools/test_ngram_speculative.py
bash -n tools/run_adaptive_ngram_gate_remote.sh
git diff --check
```

Add explicit negative artifact tests that mutate one source file, one patch
byte, the tree hash, and the remote-test return code.

### Remote Smoke

After Kerberos/SSH access is available:

```bash
RUN_TAG=20260717-k1-sam-smoke \
MODEL_PATH=/data00/home/sitian/sitian-workspace01/.ms_cache/Qwen/Qwen3-0___6B \
```

Required evidence:

- remote source preflight passes;
- remote K1 regression passes;
- 20/20 gate rows complete;
- all rows use unique pairs of dynamic ports;
- exact outputs match baseline;
- downloaded source reconstruction and artifact verification pass.

### Remote Canonical

Only after smoke:

```bash

MODEL_PATH=/data00/home/sitian/sitian-workspace01/.ms_cache/Qwen/Qwen3-0___6B \
```

Required evidence:

- 140/140 rows across seven repetitions;
- all smoke source requirements still pass;
- baseline and K1 outputs are token-identical;
- the precommitted performance thresholds decide `GO` or `NO_GO`;
- local full artifact verification passes after download.

## Commit and Claim Gate

The K1 fast-path files remain uncommitted while implementing and locally
validating SAM evidence.

They may be committed only after:

1. remote K1 regression passes against the recorded source tree;
2. canonical rows and repetitions are complete;
3. exact-output gates pass;
4. full source reconstruction passes;
5. the existing performance gate passes.

If correctness passes but performance does not, retain the SAM machinery and
record K1 as `NO_GO`; do not commit or advertise the fast path as an
optimization. If infrastructure or source evidence is incomplete, make no
performance conclusion.

## Claim Boundaries

A successful result proves only that the recorded dirty K1 implementation was
executed and measured reproducibly on the recorded Qwen3-0.6B remote gate.

It does not prove:

- production batching or queueing behavior;
- non-greedy equivalence;
- other models or hardware;
- decode acceleration outside the measured K1 path;
- lower KV memory, larger context capacity, or lower model weight memory;
- runtime integration readiness.
