# 四题开发实验的固定远程驱动

日期：2026-11-17。本文把已定的 D01–D04/base/text 两轮流程接到已验证的
远程底座与隔离执行器。它是下一集成阶段设计，不是已完成的运行或启动凭证。
协调器及新运行包仍须完成各自独立审查。不得恢复旧会话、重放已消费入口、
重训、加载适配器或提前执行迁移/保留任务。

## 选择

采用新的、单次使用的固定驱动，复用已接受的组件和不变的 launcher/worker。
不修改并重放旧 smoke：旧入口及其证据已封存，且其固定消息不是开发题。
不另建通用远程作业系统：本阶段只需要一个串行运行及完整失败证据。

协调器负责固定顺序、调用上限、公开反馈和评分；驱动负责真实模型、
运行时、隔离启动及原始产物关联；本地独立验证负责复核完整结果。
三者分开，不把调用方自报 hash 当作真实运行证明。

## 固定输入与一次性身份

- 输入仍为冻结的 source、manifest、supervision、prompts 四份原始字节，
  由原加载器验证其 hash。仅可信驱动/评分侧持有完整材料。
- 固定四题八个 episode，顺序及逻辑 ID 由已接受排程产生；不依据输出
  选择任务、改顺序、替换提示或增添生成机会。
- 准备阶段固定唯一 run_id、程序及完整本地模块清单、launcher/worker、
  运行时、底座 checkpoint/tokenizer 身份、GPU 身份和单次执行限制。
  模块清单也覆盖驱动的辅助依赖，而不只覆盖协调器的声明字段。
- 新的本地一次性 claim 与远端独占目录均不复用。claim 或传输已消费后
  不通过换目录、换 ID 自动补跑。断线保留已知状态及未知区间，先读取
  现有结果判断状态，不能把没有收到 DONE 视为没有执行。

## 真实底座绑定

复用已完成真实 smoke 中经过验证的准备步骤，不调用其入口：

1. 核对远端主机/用户、Python 隔离参数、既有离线依赖和所用源文件。
2. 核对目标 GPU 身份及空闲状态，不终止或挤占其他人的进程。
3. 校验 checkpoint 文件的大小/hash 及读取前后文件身份。
4. 离线加载原 BF16 eager 底座，eval、无梯度、无适配器、无 KV cache。
   保留原模型层数、dtype、base-state/tokenizer-state 完整性检查。
5. 固定随机性设置；保存初始状态，结束或失败时尽可能核对未变更状态。

不安装包、下载模型、改变共享服务、传递凭据或弱化认证。
历史成功说明该路径曾工作；实际可用性以新运行的检查为准，不从旧票据
日期推断本次认证成功或失败。

## 三个真实回调

`generate` 只接收协调器提供的当前公开 messages、call_id、期望 tokenizer
摘要和独占产物目录。绑定原 `generate_observed`：

- 在同一次逻辑调用内保存真实 tokenizer 测量及其提示摘要；
  不另外发起模型请求。
- 保留原观察式生成的 claim、generation、observation 和清理诊断。
- 成功时核对真实测量与输入 token 数、提示 hash、输出 token/解码文本、
  tokenizer 身份和 CUDA 执行证据。生成器自己已进行的限制检查不能被
  驱动的补充核对替换或放宽。
- 如果第二轮超过4096输入 token，保留该次原观察式拒绝及已完成首轮成本；
  不截断、改写、重试，也不额外复跑旧4097 smoke。

`execute_public` 与 `execute_final` 分别绑定对应的已接受准入执行器，
不能把最终请求伪装成首轮请求。两者复用同一份已固定的隔离 launcher/worker。
每个子进程只收到单个无答案 payload，不获得私有期待值、完整计划或模型。

每次执行保存准入、父进程观察、回执和 stdout/stderr/control 原始字节。
核验既有启动诊断及17项固定检查，不能把“之前有一次通过”替代本次证据。
worker 在输入前输出的 `generated_candidate_executed=false` 等固定字段
只描述该时点；不能据此否认随后发生的候选执行。

## 失败与成本

驱动确认的身份、协议或隔离违例用 `BoundaryProtocolError` 表达。
无法归因的回调/传输/持久化失败保持基础设施不完整状态，不自动计为
模型答错、政策拒绝或免费重试。协调器保持原异常和部分报告。

模型加载、GPU/文件校验、共享准备、协调器执行及驱动外层 wall 分层报告。
嵌套时间不重复相加；未知值为 null。无论是否正常结束，都尽量导出已经
存在的证据、原异常、次生保存错误和当前调用位置。导出失败也须单独保留。

不新增聚合内存/磁盘预算或断线自动清理前提。保留已有单次执行限制、
独占目录、不干扰他人和实际子进程回收检查；不因用户取消聚合预算而
移除既有隔离措施。

## 新运行包与验收

在任何实际 SSH 执行之前，核验新包的完整源文件与传输字节、模块依赖
顺序、冻结输入绑定、唯一 claim 和回调绑定。旧 prepare/run/close 程序
均只作文本参考，不复用已消费的执行入口。

新包不沿用旧 smoke 把完整源码塞入单个 `python -c` 参数的方式。
源码与冻结字节通过 SSH 标准输入传递；小型固定 bootstrap 在读取完毕、
校验预先固定的字节长度与 SHA256 后，才解释包内数据并进入驱动。
不对尚未传完的输入执行 Python，不通过拆成多次模型调用绕开参数大小。
固定包长度用于完整性核验，不是新增聚合内存/磁盘预算。

本地先用合成资料验证驱动的证据收集、成功/失败导出和固定回调绑定，
不在本地加载真实底座或执行生成候选。新包经独立审查后才进入真实运行。

事后验证从保存字节独立重建每次执行回执、八个位置、十六次计划生成、
完整最终用例分母、首轮无效历史及成本。核对真实模型/运行时与隔离诊断，
而不是仅相信 coordinator 的 completed 字段。

完成开发流程也不是 LoRA 有效的证据。报告区分过程完成、题目通过、
开发校准、隔离/来源核验及后续研究准入。校准不满足时不得自动启动32题；
校准满足时也不自动宣布泛化、经济收益或部署资格。
