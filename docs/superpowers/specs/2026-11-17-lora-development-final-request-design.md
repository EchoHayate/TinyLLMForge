# 开发阶段最终候选请求

日期：2026-11-17。接续已批准的 D01–D04、base/text、两轮开发流程；
按用户要求连续实施，不重复要求常规继续确认。此组件不启动实验。

## 选择和范围

现有 `candidate_execution_protocol.py` 仅接受 round=1、P01/P02。
不能给第二轮候选或私有评分输入换上这些标签，再把它称为最终评分。
直接扩展旧协议会改变已封存接口；现在选择新增独立的最终请求协议，
复用相同的单用例 worker 负载与纯源码/JSON 预算检查。
不修改旧协议、准入、控制器、worker、题库或生成实现。

本次只实现请求校验和负载构造，不实现评分、进程启动或整段开发流程。
它不是候选安全准入，也不能单独证明用例来自冻结评分集。

## 接口

新增 `experiments/lora_necessity/development_final_protocol.py`：

`prepare_request(request) -> (request_sha256, payload_bytes)`

request 必须是仅含下列字段的普通 dict：

- `kind`: 精确字符串 `LORA_DEVELOPMENT_FINAL_REQUEST`。
- `version`: 精确 int 1；`round`: 精确 int 2。
- `run_id`、`attempt_id`、`generation_call_id`: 各为 32 位小写十六进制。
- `generation_sha256`、`case_set_sha256`: 各为 64 位小写十六进制。
- `task_id`: D01–D04；`arm`: base 或 text。
- `case_group`: public 或 scoring。
- `case_id`: 以 ASCII 字母开头，后跟 0–31 个 ASCII 字母/数字/下划线/连字符。
  public 只接受 P01/P02；scoring 不接受 P01/P02。
- `entry_point`、`source`、`args`: 沿用旧协议的单函数源码与单用例参数约束。

所有身份字段必须先检查精确类型，再作比较。bool 不得作为 version/round。
args 是普通 list；整个请求只允许原生 JSON 类型，拒绝子类和自定义对象，
且在摘要/序列化前完成有界检查，不触发这些对象的自定义行为。
复用旧协议 `_source` 和 `_json_budget`；不调用旧 `prepare_request`，
不创建一个假 round-one 请求，不修改旧模块的全局函数。

返回摘要为整个新请求的现有规范 JSON SHA256。负载仍是仅包含
`source`、`entry_point`、`args` 的规范 JSON 加一个换行，沿用 1 MiB 上限。
完整请求另有 1,052,672 字节的规范 JSON 上限，防止元数据绕过负载预算。
源码 UTF-8 上限 65,536 字节。返回 bytes 固定后，后续调用方修改输入不能
改变已经返回的摘要/负载。语法、类型、深度、预算或编码错误均抛 ValueError。
不调用源码中的函数，不导入模型，不连接远程，不写文件，不读取题库。

## 与后续组件的关系

generation_call_id/generation_sha256 必须在后续可信协调器中核对到真正的
第二轮生成记录；case_set_sha256 必须核对到固定完整的最终用例集合。
本层只验证格式及摘要绑定，不能把调用方自己填的摘要当成这两种证明。
只有后续独立审查的最终准入、执行控制器、用例来源检查和完整评分器共同
通过后，才允许执行最终候选或给出通过成绩。

最终开发验收采用公开用例与独立评分用例的并集，全部通过才是功能通过。
公开/评分组别保留，最终结果不回传模型。这个选择保留已知公开要求，
不会把首轮公开反馈复用成第二轮执行结果；不增加生成次数或重选候选。
此组件不读取这些实际用例，也不决定后续真实启动的用例数量/时限。

## 测试与验收

先使用完全合成的请求写缺失组件 RED，再实现 GREEN：

- 正常请求、完整身份摘要与只含三个字段的 worker 负载。
- 任一身份、组别、源码、参数变化都会改变完整摘要；外部输入后续修改不
  改变已返回 bytes；格式不同但值相同遵循现有规范序列化规则。
- 拒绝首轮请求、T/R/监督任务、LoRA 组、组别/用例混淆、额外/缺失字段、
  错误类型、非有限数、子类/自定义对象、预算/深度/编码/语法违规。
- 源码中死循环或异常语句不会在校验时执行；安全上不允许的计算仍须由
  后续最终准入拒绝，不能把语法校验测试写成安全执行证明。
- 明确验证旧协议仍拒绝新请求，旧首轮请求仍按原样通过。
- 不读取冻结私有题目，不运行真实模型或候选，不导入 Torch。

独立审查后才能用于后续最终执行组件。当前真实底座 smoke 已通过，但它
不能替代此最终评分通路，也不能证明 LoRA 有增益。
