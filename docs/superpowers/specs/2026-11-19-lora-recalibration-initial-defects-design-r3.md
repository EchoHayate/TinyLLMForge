## 2. C04：用共享总账快照差冒充独立事务金额

入口和合法域仍为原`transaction_totals(events)`。初始算法假设每个事务
从begin到结束期间，全局总账的变化都属于它，因而把串行可用的快照差用于
可交错事务。唯一根因是错误的金额归属表示，而不是漏掉生命周期事件。

拟议错误算法精确定义：

1. 初始化整数全局累计值`total=0`、空的`starts`字典和提交结果列表。
2. begin：保存`starts[transaction]=total`，即这个ID开始时的总账快照。
3. add：只做`total += amount`，不区分amount所属的事务ID。
4. commit：移除该ID快照，立即追加
   `[transaction, total - starts.pop(transaction)]`，不再改变全局total。
5. rollback：先移除该ID快照，再将全局total恢复为该快照，即
   `total = starts.pop(transaction)`；不输出。
6. EOF只返回已经追加的提交记录，不输出未结束事务。

第4步中的表达式描述取值顺序：读取当前total与被移除的快照相减；
不重复pop、不减错ID、不创建延迟可变输出对象。每个合法终止的目标快照
必存在，begin只用于不活跃ID；因此不引入缺键或故意异常。
输出次序就是原commit事件次序，所有事件种类和ID查找都已正确。

这是一种完整而错误的“全局前缀和+每次开始快照”模型：
串行事务的差值与回滚可工作；多个事务同时活跃时，外来add进入每个人的差值，
回滚还撤销别人的变化。没有额外加错比较符、金额符号、输出排序或归零故障。

### 实际修复义务，而非指定补丁

需要恢复金额变化的事务归属，使某ID的add与终止不改变其他活跃ID的净金额。
可以使用独立的按ID累计值，也可重扫各生命周期的日志，或设计正确的共享
账务补偿。不能要求必须用字典、必须改多行或必须照抄参考A。

一个等价的“仍保留全局总账”的手工可行修复也应被允许：
本事务add后，将同一amount同步加到每个其他活跃事务的开始快照，使其
total-starts差保持不变；本事务rollback恢复快照前算出其差值，再从每个
其他活跃快照减去这个差值，使它们不受全局回退影响。begin/commit可保留。
这说明不能以必须换数据结构为准入理由，但它仍需要完整的按ID账务隔离，
不只是C10的移尾或C11的首次资格门控。此方案不新增为第三参考或错误变体。

## 3. 公开见证与最小修复检查

原P01手推状态如下；starts只显示仍活跃的ID。

| 事件 | total | starts | 输出 |
| --- | ---: | --- | --- |
| begin a | 0 | a:0 | 无 |
| begin b | 0 | a:0,b:0 | 无 |
| add a 5 | 5 | a:0,b:0 | 无 |
| add b 2 | 7 | a:0,b:0 | 无 |
| rollback a | 0 | b:0 | 无；错误撤掉了b的2 |
| begin a | 0 | b:0,a:0 | 无 |
| commit a | 0 | b:0 | a0 |
| commit b | 0 | 空 | b0 |

预测错误结果`[["a",0],["b",0]]`，正确仍为`[["a",0],["b",2]]`。
未来initial见证仍绑定原公开P01，不新增评分参数。

针对最小修复的检查：

- R1“将目标移至末端”没有作用：这里按目标ID查快照已经正确，
  字典内部次序完全不参与计算；重排也不能把total7中的a5和b2分开。
- R2/C11“只让合格事件锁定首次位置”没有作用：所有事件及ID都合法，
  没有首次候选选择/错误排序；金额已经在add时无归属地混入共享total。
- S03的begin归零不能修复：H05三个begin本来都存0，随后所有事务仍看到6。
  若一概把快照存0，还会让H03第二次串行提交从正确1变为5。
- 仅取消rollback时的全局恢复不够：P01会输出a0/b7，而不是a0/b2。
- 仅在终止时正确pop目标不够：该操作已正确存在，污染发生在共享金额表示。

H05还提供状态不可区分说明：a1/b2/c3与a2/b1/c3两种合法历史，在全部add后
都形成total6及三个零快照，却应分别先提交b2或b1。当前这份状态本身不保留
各ID贡献，不能只改末尾排序或比较符恢复。第二种历史仅为手工论证，不加入
题库或作为额外模型测试。完整输入日志仍在，允许正确程序通过重扫恢复归属；
不把“当前状态丢信息”夸大成输入整体不可恢复。

| S02 | D | 不是半开交长多加一，外来amount不因端点算式变化消失 |
| S03 | M | 累计生命周期共享；H05各快照本来为0，补归零不能拆分并发贡献 |
| S04 | M | 状态隔离共享；每begin清总账会破坏其他活跃事务，不是逐行独立seen清空 |
