# Qwen3.5 TP KV-Head Replication Design

## Objective

Allow Qwen3.5 full-attention layers to run with tensor-parallel sizes larger
than the model's global KV-head count while preserving exact checkpoint
values:

```text
global query heads = 8
global KV heads = 2
TP size = 4

rank0: query shard 0, replicated KV head 0
rank1: query shard 1, replicated KV head 0
rank2: query shard 2, replicated KV head 1
rank3: query shard 3, replicated KV head 1
```

This is the standard grouped-query-attention replication policy used when
`global_kv_heads < tensor_parallel_size`.

## Failure That Motivates the Change

The authoritative TP4 real-candidate run
`qwen35-tp4-real-candidate-replay-20260728-140507` failed before checkpoint
loading with:

```text
ValueError: num_key_value_heads must be divisible by tensor_parallel_size
```

The approved checkpoint has:

```text
num_attention_heads = 8
num_key_value_heads = 2
head_dim = 256
```

The current component factory requires every head count to be divisible by
TP size and uses a generic column-parallel K/V projection. That generic
projection would split a 256-wide KV head into partial-head shards at TP4,
which is invalid.

## Selected Policy

For full-attention KV heads:

1. if `global_kv_heads >= TP`, require `global_kv_heads % TP == 0` and shard
   heads normally;
2. if `global_kv_heads < TP`, require `TP % global_kv_heads == 0`;
3. each rank owns one complete local KV head;
4. `replica_count = TP / global_kv_heads`;
5. `source_kv_rank = tensor_parallel_rank // replica_count`;
6. ranks with the same `source_kv_rank` load identical K/V checkpoint rows.

For the approved model at TP4:

```text
replica_count = 2
source_kv_rank = (0, 0, 1, 1)
local_kv_heads = 1 on every rank
```

## Components

Add a dedicated KV-head parallel linear layer rather than weakening generic
`ColumnParallelLinear`:

- stores complete local KV heads;
- records global KV heads, local KV heads, replica count, and source KV rank;
- loads one complete contiguous source-head shard;
- preserves the existing normal-sharding behavior when KV heads are at least
  TP size.

Use it only for Qwen3.5 full-attention K and V projections. Query and output
projections remain unchanged.

## Checkpoint Binding

The checkpoint binding plan must recognize the dedicated KV projection:

- source shape remains the global `[global_kv_heads * head_dim, hidden]`;
- destination shape is
  `[local_kv_heads * head_dim, hidden]`;
- the custom loader selects `source_kv_rank`, not raw TP rank;
- TP4 ranks `(0, 1)` therefore load the same K/V source rows, and ranks
  `(2, 3)` load the other rows.

No producer row, payload hash, or layout fingerprint may be copied or
synthetically rewritten. They must be regenerated by real TP4 loads.

## Validation

Focused tests must prove:

- TP1 and TP2 behavior remains unchanged;
- TP4 component construction succeeds for `8Q/2KV`;
- every rank reports two local query heads and one local KV head;
- K/V projection destination shape contains one complete 256-wide head;
- rank0 K/V payload equals rank1;
- rank2 K/V payload equals rank3;
- rank0/1 payload differs from rank2/3 for distinct source values;
- invalid non-divisible replication, such as `3 KV heads / TP4`, fails
  closed;
- existing checkpoint binding, assignment, candidate factory, and full
  attention tests remain green.

After focused validation, rerun the TP4 real-candidate provenance gate with a
new unique tag. The earlier failed run directories remain immutable evidence.

## Claim Boundary

Passing this feature proves correct construction and checkpoint loading for
replicated full-attention KV heads. It does not by itself prove model output
correctness, quality, latency, throughput, cache savings, or live concurrent
TP4 candidate ownership.

## Final Evidence

The implementation and remote real-checkpoint gate completed successfully.
For the approved `8Q/2KV/TP4` topology:

```text
local query heads per rank:
  2
local KV heads per rank:
  1
KV replica count:
  2
source KV ranks:
  (0, 0, 1, 1)
```

Focused tests proved normal TP1/TP2 sharding, TP4 replication, invalid
topology rejection, component construction, replicated binding shapes, and
rank payload grouping. The final source-bound real run is
`qwen35-tp4-real-candidate-replay-20260728-145713`, with source tree
`42dddc0eac0a6db6041d5abb71df34db4d5e7c99d3b74d69f94598a2f24eb137`.

The real producer rows were regenerated independently for all four ranks; no
TP2 row or payload hash was copied or rewritten.
