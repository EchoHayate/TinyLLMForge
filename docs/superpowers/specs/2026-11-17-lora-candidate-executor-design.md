## 2. 方案选择

| 方案 | 取舍 |
| --- | --- |
| 直接把候选 stdout 当完整收据 | 实现最少，但候选可以输出请求身份、状态或“pass”；不采用 |
| 隔离外控制端生成收据，每个用例独立隔离子进程 | 沿用现有 Python 与隔离证据，把身份、生命周期和判分留在候选外；采用 |
| 新建受限 Python 解释器或更换 VM/container 后端 | 引入新的语言或运行环境差异，不能复用当前验收；不在本阶段做 |

不把 AST/import 限制当成安全隔离，不因已有静态检查而绕过子进程。
控制端不 `exec`、`eval`、导入或运行候选源码。

## 3. 信任边界

### 控制端拥有的事实

- 通过 `visible_requests` 构造的完整请求及其 canonical SHA256。
- 唯一 attempt_id、task_id、arm、round、case_id、顺序和单次执行记录。
- 自己启动的进程句柄、读取的字节数、单调时钟和实际退出状态。
- 固定的限制及运行时、启动器、执行器源码摘要。
- 是否有完整合规结果，是否由控制端触发超时或输出超限终止。

候选输出不能覆盖这些字段；控制端不接受候选自报的 `status`、
`request_sha256`、`elapsed_seconds`、`pass` 或 `mismatch`。

### 候选返回的数据仍不可信

子进程只提供单个用例的结果数据。公开 expected 留在原反馈组件，
不传给执行子进程；最终 `pass/mismatch` 由 `visible_feedback` 计算。
模型仍只收到用例编号和现有分类，不接收原始输出或栈。

独立结果管道不是认证机制：候选与 Python 包装器处于同一解释器，
不能仅凭管道或 JSON 格式宣称“返回事件绝不可能被候选伪造”。
本阶段能验证身份和生命周期由父进程掌握，不能因此宣称全面防篡改。
尤其不把候选返回的字典当执行器异常或收据；它只能作为普通返回值。

固定的结果伪造样例必须覆盖普通 stdout 伪造、结果通道多记录、
返回收据形状字典和包装器状态干扰。若能绕过包装器把控制数据当成
真实函数返回/异常，不得声称候选执行准入完成，也不得静默把研究任务
从“调用函数的实际结果”改成“比较任意打印文本”。

## 4. 组件与数据流

计划新增文件，保持既有组件不变：

- `experiments/lora_necessity/candidate_execution_protocol.py`：
  严格解析子进程结果；根据控制端观察生成现有格式收据；
  无进程启动、无候选执行、无远端配置。
- `experiments/lora_necessity/candidate_execution_controller.py`：
  单次启动、握手、限量管道收集、计时、终止、回收和本地运行记录；
  不持有任何任务期望答案，不接受来自子进程的请求身份。
- `experiments/lora_necessity/candidate_execution_worker.py`：
  只在隔离子进程内接收单个源码/入口/args、调用函数、形成有界结果。
  不自动导入执行；普通导入或本地测试不能启动候选。
- 对应三个 `test_candidate_execution_*.py` 文件：
  本地只使用合成事件或受审阅的固定辅助程序。

含内部路径的启动配置、运行命令和原始远端记录留在私有阶段目录。
发布的组件没有默认远端地址、账户目录或凭据路径。

每个公开用例：

1. 调用者用现有公开请求接口验证来源；控制端保存完整请求及摘要。
2. 先记录单次 claim，再启动固定可信启动器。重复 claim 直接拒绝。
3. 启动器复用 V3 的运行时 pin、宿主禁提权、命名空间隔离、
   capability 清零和默认拒绝过滤规则；任何前置步骤失败不得回退。
4. 子进程只运行可信初始化；尚未收到候选源码。
5. 控制端收到有界、精确匹配的初始化就绪消息后，才发送
   `source/entry_point/args`，不发送整个请求或 prompts 文件。
6. 一个新子进程仅执行一个用例；不复用解释器或可写工作目录。
7. 控制端收齐结果、所有输出 EOF 和退出状态后，形成收据和独立审计记录。
8. 两个用例的收据按原顺序交给 `visible_feedback`，再进入原第二轮提示。

初始化握手和结果使用专用管道；普通 stdout/stderr 只计量和留有界诊断。
专用管道在候选开始运行后仍属于不可信子进程，按第 3 节处理。
启动失败不发送候选，也不生成看似正常的候选测试失败收据。

## 5. 限制与状态

本轮拟固定以下执行器限制，在接触模型输出前确认，不按结果调参：

- 源码继续使用既有 UTF-8 65536 字节上限，不裁剪、不修补。
- 单次发送的 JSON 输入至多 1048576 字节，超限在启动前拒绝。
- 可信初始化墙钟至多 10 秒；候选请求开始发送起墙钟至多 10 秒。
- 沿用固定探针的 CPU 3 秒、禁止 core dump、普通文件写入 4096 字节限制。
- stdout、stderr、握手和结果管道累计至多 65536 字节；
  单个结果至多 16384 字节，初始化消息至多 4096 字节。
- worker 返回值只接受精确的内置 JSON 类型，递归深度至多 32、
  遍历节点至多 4096；该结果结构限制不施加到输入 args。
  控制端协议在解析不可信结果前另检查最多 128 层容器嵌套。
  这些限制在运行模型候选前固定，所有组相同。
- 每次读取至多 8192 字节；不先无限缓存、再检查输出上限。
- 控制端正常终止自己的子进程后最多等待 2 秒回收；无法确认回收则
  记录基础设施失败，不继续启动下一项。

这些是逐次执行和反馈协议限制，不恢复用户已取消的全流程内存/磁盘预算，
也不将断连自动清理重新列为准入条件。不新增安装或共享服务修改要求。
无法保证 CPU 终止原因时，不仅凭一个 SIGKILL 就断言是超时。

收据保持现有格式：

- `completed`：控制端确认正常退出且仅有一个合规 outcome。
  outcome 只能是 `return/value` 或 `raises/ValueError`。
  不由 worker 或协议解析器判定 pass/mismatch。
- `program_error`：候选开始后非正常退出、不支持的异常、
  非法/重复/多条结果、无结果或不支持的结果类型。
- `timeout`：控制端实际触发候选阶段的墙钟期限终止。
- `output_limit`：控制端实际观察到输出或结果字节超过预定上限。

不完整连接、启动/握手失败、管道收集器故障、回收失败、身份或源码
摘要不符属于基础设施失败：停止当前批次，不映射成模型可修复的普通反馈。
CPU 信号及其退出原因保留原始审计值；若未被上述规则可靠归类，
先报告 `program_error`，不伪造测量。
候选期超时与输出超限以控制端首次触发的终止原因固定，
之后收到的尾部结果不能将其覆盖为成功。

严格 JSON 拒绝重复键、额外字段、无效 UTF-8、非有限数值及超深输入。
返回值类型不能通过布尔/整数或浮点/整数转换“修正”成期望值。
没有完整退出/EOF 的中间结果不得作为成功收据。
worker 对序列化超限只发送真实 JSON 的前 16385 字节，由控制端实际观察到
越界并分类；不把超大结果的内部编码异常误称为普通函数异常。

共享 Python JSON 编码函数和 builtins 篡改属于必测项。
当前实现策略是在调用前保存 C 编码器、类型/异常身份与输出构造器，
让结果检查使用独立的内置函数字典。该策略针对已列举的共享状态问题，
不宣称防御任意 native 内存写入或解释器内部 frame 篡改。

## 6. 本地与远端验收

本地先测试协议纯函数和控制端状态机，使用合成观察，不运行实验任务：

1. 正常返回、ValueError 和其他异常分类；bool/int 不混淆。
2. 打印伪造 pass、请求摘要、timeout 不影响控制端事实。
3. 返回收据形状的字典仍是普通返回值。
4. 重复键、多条结果、附加字段、无效编码、非有限数值均拒绝。
5. 超时/输出超限已触发后，晚到的合法结果不能覆盖失败原因。
6. 缺失 EOF、启动失败、握手超限和回收失败不能产生正常完成。
7. 重复 claim 拒绝；一次失败不自动重试。
8. 两个公开请求到现有反馈与第二轮渲染的合成衔接，保留原始分母。

新启动器/worker/控制端经独立审查后，在远端只运行固定诊断：

- 正常返回和预期 ValueError。
- 非预期异常、主动非零退出、没有结果而退出。
- 死循环，以及 stdout/stderr/结果通道的输出超限。
- 合法结果后继续运行或继续输出，不能提前计成功。
- 普通输出伪造状态、多个结果、收据形状返回值和包装器干扰。
- 两个独立用例间不能继承可写状态。
- 子进程实际不可见答案目录、凭据、宿主控制状态；权限及过滤不退化。

诊断输入单独编写，不读取冻结任务源码、监督答案或隐藏评分文件，
不调用模型、不训练、不重跑此前 1416 项固定验证。
本地合成测试通过不能替代远端生命周期和隔离验收。
未通过的检查原样记录，未经审查不放宽系统调用规则或自动换后端。
