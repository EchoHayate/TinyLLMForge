## 3. C01：过期释放发生在准入判断之后

入口仍为 `admit_reservations(capacity, requests)`；所有参数和正确结果不变。

拟议错误控制流精确定义：

1. 初始化空的已接受预约列表和布尔结果列表。
2. 每个请求按原输入次序进入，包括同刻请求。
3. **先**对当前保存的预约求占用量，比较占用加当前size是否不大于capacity。
4. 追加本次决定；仅在接受时保存当前 `[size, expires]`。
5. **最后**过滤保存的预约，只保留 `expires > time` 的项，再处理下一笔。

只存在一个根因：决策使用了尚未按当前时刻清理的历史集合。
恰满比较正确、过期等号正确、仅接受才入账正确，没有第二个故障。
新请求合法地满足expires>time，因此末尾过滤不会误删刚接受的当前请求。

必要修复义务是让当前准入使用当前时刻仍有效的已接受集合。可以把过滤
移动到求占用前，也可在占用求和时应用有效时间条件；不强求某种补丁。
仅修改等号不能改变“已经用陈旧占用作出决定”的因果顺序；不能套S01。
忽略占用或逐请求清空全部预约会错误接受P01第二笔，不能作为等价修复。

## 4. C04：误把交错事务当作嵌套栈

入口仍为 `transaction_totals(events)`；只接收原规格的合法生命周期，
没有新增“必须嵌套”的题面限制。

拟议错误控制流精确定义：

1. 初始化空栈，栈元素为独立的 `[transaction, total]` 记录。
2. begin一律在栈尾追加该事件ID和零金额，不复用旧ID金额。
3. add忽略事件中的目标ID，将amount加到当前栈尾记录的金额。
4. commit移除栈尾记录，输出 `[本commit事件的ID, 被移除记录的金额]`。
5. rollback只移除栈尾记录，不输出。
6. 流末尾返回已有提交记录，不输出未终止项。

单一根因是把“最近begin的事务”当作后续任何add/终止事件的所有者。
三处使用栈尾是同一错误状态模型的传播，不是三个独立bug。
所有记录独立分配，禁止另外加共享列表别名、错误金额或错误输出次序。
合法域中begin数减终止数就是非空活跃事务数，错误栈长度也遵循这个数；
所以add/终止访问栈尾时不会仅因交错而下溢。目标是语义错误，不是异常。

修复必须按事件ID定位**金额更新和终止对象**，同时保留其他活跃事务。
允许字典实现，也允许在列表中查找匹配ID并更新/移除，不能强求改数据结构。
只归零、只删除本键或只修一处输出标签不足以修复该模型。
不能用正确参考实现的长度证明结构差异；下面直接检查更小的局部补丁。

### 手推公开见证 P01

原事件的begin a、begin b后，栈为a0/b0；add a5错误写到b，使b5；
add b2使b7；rollback a错误弹出b7，留下a0；再次begin a追加另一a0。
commit a弹出新a0并输出a0；commit b弹出遗留a0但以事件ID输出b0。
错误结果为`[["a",0],["b",0]]`，正确仍为`[["a",0],["b",2]]`。

两个单点捷径都不够：

- 仅按ID修add，终止仍弹栈尾：P01最终输出a0/b5，仍不等于a0/b2。
- 仅按ID修commit/rollback，add仍写栈尾：P01最终输出a0/b7，仍错误。

这两条仅为手推反驳简单补丁，不新增成评分用例或第三/第四个变体。
