## 1. 目标与不变条件

唯一目标是回答两项准备问题：

1. 能否用冻结的独立期望值，完整检查参考实现及已知错误实现的实际行为？
2. 同样的八例监督信息及两轮修复流程，能否满足真实 tokenizer 的长度限制？

第一项先交付不执行源码的控制逻辑，实际行为仍需获准隔离后端取得。
第二项先交付确定性提示构造与计数接口，真实长度仍需经核验的目标
tokenizer。模拟结果不得变成真实通过记录。

沿用 `2026-11-10-lora-necessity-pilot-design.md`：

- 8 个监督题、4 个开发题、16 个迁移题、16 个保留题。
- `base`、`text`、`lora`、`lora_text` 四组，开发题只运行前两组。
- 主要比较 `lora_text` 对 `text`，两组完整示例段逐字节相同。
- 每题每组两轮、每次输入最多 4096 token、输出最多 256 新 token；
  模型调用总上限 272，不因首轮通过省略第二轮。
- 保留既定 16 步梯度配置、筛选门槛和正式流程 3600 秒预算，不实现训练。
- 不改 44 题、评分用例、阈值或既有合成计分 API，不接主推理引擎。

这里的题库动态审计不是 272 次模型生成，也不是正式模型流程。
其实际启动需要独立的执行预算，不能借用正式流程预算获得启动许可。

## 2. 路线选择与已有实现

| 路线 | 判断 |
| --- | --- |
| 直接调用旧固定程序执行器 | 不采用；没有本任务要求的安全隔离，也不支持当前通用题目协议 |
| 先实现完整训练及生成链路 | 不采用；无法提前解决答案可信度和文本基线长度问题 |
| 独立控制端、独立提示/token 检查，后端另行接入 | 采用；本地逻辑可先验收，不把环境依赖伪装成已交付能力 |

可借鉴 `experiments/feedback_adaptation/selection_model_contract.py` 中
请求、模板和 token ID 的绑定思想，但不直接导入其选择题合同。
旧合同固定 118 次调用、单轮提示及 32 token 输出，不适用于本任务。
`selection_model_preflight.py` 的预检还依赖旧 worker、生成配置和模型包；
本组件不为计数而加载基础权重或调用旧 worker。

`fixed_program_smoke.py` 在宿主调用固定函数，不是隔离执行器。
AST 检查、子进程超时、Agent 权限模式也不替代候选执行隔离。

2026-11-11 的只读发现仅用于准备：
常见本地命令路径未发现 Docker、Podman、bubblewrap，发现 `sandbox-exec`；
未做其安全能力验收。常用 Hugging Face 缓存未发现 Qwen3-8B。
这些是有限路径检查，不是全机穷尽搜索，也不推断远程环境今日状态。

## 3. 两个组件及文件边界

拟新增文件均位于 `experiments/lora_necessity/`：

| 文件 | 单一职责 |
| --- | --- |
| `validation_contract.py` | 冻结数据身份、生成完整执行清单、分离工作请求和控制端期望值 |
| `validation_report.py` | 严格解析模拟观察、外部比较、完整性与错误见证报告 |
| `prompt_rendering.py` | 监督示例、训练消息、首轮与第二轮消息的确定性构造 |
| `token_budget.py` | 注入 tokenizer 的计数接口、身份绑定、超限拒绝和报告 |
| 对应四个 `test_*.py` | 标准库测试；模拟观察与替身 tokenizer，不执行题目源码 |

实施计划分为“控制端合同与报告”和“提示构造与 token 预算”两份。
前者不依赖后者，可以独立审查；后者不读取动态审计的私有评分结果。
数据格式和字段校验归属前者，但后者只能得到显式投影出的公开数据。
不建设通用插件系统，不复制旧 supervisor、SSH 或 GPU 生命周期框架。

本轮后续本地实施不含：执行 worker、隔离后端适配、真实 tokenizer 加载
入口、训练 worker、模型生成、正式效果计分器或远程部署工具。
这些缺项不能用一个调用方传入的 `isolated=true` 或 `real=true` 消除。

## 4. 动态核验清单

以当前题库每题的全部公开及评分用例为准，对四种源码分别安排一次：
参考、初始错误、M01、M02。固定顺序为题目 ID、源码角色、公开/评分、
用例 ID；不随机、不重试、不按早期结果删减。

当前共有 88 个公开用例、266 个评分用例，合计 354 个；
四种源码形成 **1416 个预定执行项**。这是清单规模，不是已运行或通过数量。
本方案不自动增加重复执行，因而不宣称验证了跨运行确定性。

每项控制端记录绑定：

- 当前源码包、完整任务、实际函数源码、用例输入和期望值的摘要。
- 题目、源码角色、公开/评分类别、用例 ID 及唯一清单序号。
- 入口函数名、参数结构、期望为返回值还是 `ValueError`。

工作请求只含当前函数源码、入口和当前参数副本，以及无答案含义的关联 ID。
不含正确期望值、错误预测、其他源码、推导理由、整个题目对象或文件路径。
后端将来不得通过挂载目录重新暴露这些信息。

全清单和期望值只在控制端保存；缺失观察保持缺失，不从成功行反推分母。
不把原 `score_synthetic` 改成接收本报告的新入口。

## 5. 观察、比较与验收

执行状态与功能比较分开：

- 正常协议结果：返回结构化值，或报告本题允许的 `ValueError`。
- 程序错误、超时、输出超限、资源超限、协议损坏分别记录，无有效功能比较。
- 启动失败、观察缺失、清理失败属于执行基础设施问题，不是题目错误见证。

支持当前合同中的 JSON 值，比较时区分 bool 和 int，保持列表顺序、
嵌套结构及字典键语义；不接受浮点近似、NaN、重复 JSON 键、未知字段或
额外输出。输入类型和输出体积均应有边界；输出协议上限在真实后端方案中
与资源预算一起冻结，模拟阶段的格式检查不声称提供实际资源限制。
异常只比较允许的类型，不比较异常文本，不向模型回传栈或宿主路径。

候选与包装器处于同一不可信区域，返回字节可能被伪造。控制端仅把这些字节
当作该输入下的程序响应，绝不接受程序自报“通过”、源码身份、运行身份或
资源消耗。只有受信后端管理链路才能产生启动和清理等外部观察；
合法输出格式本身不能证明包装器内部诚实执行，也不能防止硬编码测试答案。

题库动态核验的通过条件：

1. 44 份参考实现对全部公开及评分用例符合预期。
2. 每份初始实现对指定公开见证的实际行为等于预先记录的错误预测，
   且至少一个评分用例拒绝它。不从自然语言 `reason` 解析运行指令或用例 ID。
3. 88 个 mutant 各自在结构化 `scoring_case_id` 指定的用例上产生所记录的
   错误预测，并与正确期望不符；不得用超时或崩溃代替语义错误见证。
4. 完整 1416 项观察无缺失、无执行基础设施失败；全部实例清理确认完成。
5. 数据、执行器和实际执行环境均绑定到这次获准运行，不能导入旧日志放行。

其他用例上的合法错误返回可以作为完整矩阵保留，不要求一个错误实现对所有
用例都错。若参考冲突、见证预测不成立或错误变体逃过预定见证，整批不准入；
保留原报告，另走题目更正流程，不改期望值继续追求通过。

本地模拟报告固定 `kind="LORA_VALIDATION_SIMULATION"`，只能报告
模拟清单的完整性和模拟比较。真实报告入口不在本地组件范围内。
即便模拟全部符合，`benchmark_eligible`、`formal_evaluation_ready`、
`net_benefit_established`、`isolated` 仍全部为 false。

## 6. 提示构造与信息边界

监督源只读取 `data/supervision_v1.json`；当前任务只读取
`data/prompts_v1.json`。不要向提示构造器传 `task_sources_v1.json` 或 oracle
后再依靠模板“碰巧没用到”防泄漏。

示例段按 S01–S08 固定顺序，完整包含规格、入口、初始源码、公开用例、
指定公开见证的错误预测及正确源码。字段名、排序、换行和序列化方式固定；
源码字符串不裁剪、不重排。`initial_witness.reason` 是作者推导备注，
不进入模型文本；见证通过 `public_case_id` 与结构化错误预测表达。
这样保留全部八例有效监督信息，也避免把备注中的评分用例标识带入提示。

首轮 user 内容由固定函数修复指令、可选八例段和当前公开任务组成，
四组当前任务部分逐字节相同。`text` 与 `lora_text` 使用同一份示例段，
`base` 与 `lora` 均不带历史示例；不在消息中提示组名或期望胜负。
具体消息字节由实施计划明确给出并在任何 tokenizer 检查前冻结。

第二轮保留同一首轮消息，追加首轮 assistant 候选和固定 user 反馈。
反馈只含两个公开用例的有界分类，不包含隐藏评分、栈、任意 stdout、
模型自行解释的结论或原始环境错误。公开用例的输入和期望已在首轮给出，
反馈可报告 `pass`、`mismatch`、`program_error`、`timeout`、
`output_limit`；无法解析的候选用统一 `invalid_source`，且不记作已执行。
基础设施失败直接停止，不作为可供模型继续修复的普通反馈。

训练消息逐例使用同样的公开任务字段，并保留该例结构化的初始失败见证，
避免文本示例有而训练输入没有这部分监督信息。assistant target 为该例完整
参考源码和模板要求的终止 token；不把另外七例当作该例训练输入的历史记忆。
该组件只形成训练输入与目标边界，不生成 loss、标签张量或优化器状态。

## 7. tokenizer 身份、计数与第二轮限制

只接受目标 Qwen3-8B 的经核验 tokenizer 与 chat template。
既有模型记录的 revision 为
`b968826d9c46dd6066d109eabc6255188de91218`，这是待核对的目标身份，
不是当前本地文件已存在或可加载的证明。实际准入需绑定所用 tokenizer
文件、配置、特殊 token、模板字节及库版本；不能用同系列小模型替代。

本地先用依赖注入的 tokenizer 替身验收逻辑；替身报告必须标为模拟。
真正调用 tokenizer 前另外确认文件来源和只读位置，无权重加载、
远程代码、自动下载或自动补依赖。报告身份由受信加载链路取得，
不能凭调用者提供的路径字符串证明目标模型一致。

真实计数范围：

1. 八份训练提示、目标和完整序列；明确计入模板与终止 token。
   训练提示不超过 4096、目标不超过 256；完整序列单独报告。
   完整训练序列是否满足模型和训练 worker 的容量要求留待该组件验收，
   不把“提示合规”说成“训练内存合规”。
2. 136 个预定 episode 的首轮输入，即开发 8 个、迁移/保留 128 个，
   保留组别记录，不能因两组相同就缩小清单。
3. 全部 44 份参考回答在目标回答边界的长度，包括所需终止 token，
   不以裸源码单独编码的长度代替带模板边界的实际目标。控制端另行输出
   只有题目 ID 和参考源码的私有审计投影，核对其整体摘要后供计数器使用；
   该投影不进入推理提示构造接口。模板在终止 token 后的格式尾部另行记录，
   不冒充模型生成的输出；完整序列长度仍保留供训练容量审查。
4. 已冻结的第二轮反馈格式与测试续写下的完整消息长度，以及每次真实
   第二轮调用前的完整输入长度。

固定使用同一 chat template 和关闭 thinking 的模式，记录准确 prompt
字节及 input IDs。模板渲染与直接 tokenize 的结果须相符，
不重复添加特殊 token、不静默截断。若目标模板不支持约定模式，拒绝而非
改为另一模板。目标区间必须验证完整序列与提示前缀的 token 边界；
不允许以单独编码 target 的长度相减猜测训练答案位置。

第二轮首轮候选的内容尚未产生，因此前置检查只能覆盖固定部分及注明来源的
测试续写。报告剩余空间和已检查续写，不把它命名为所有可能输出的上界；
也不声称 256 个生成 token 解码拼接后一定仍占 256 个输入 token。
实际调用前必须重编码整条消息，检查 4096 上限，并将此次 input IDs
交给将来的生成 worker 再核对。没有这一步不能报告第二轮预算全面通过。

冻结后超限即停止整次流程，保留缺失项和实际成本，判为协议不合规而非某组
模型效果差；不删文本示例、不截断候选、不放宽输出长度、不增加重试。
若需要缩短题面，必须记录新版本并重新审阅全部受影响材料。

## 8. 验证阶段与真实启动关口

本地两个计划只验证纯逻辑：

- 源/任务/用例哈希篡改、缺项、重复、乱序、错误见证链接、额外结果。
- bool/int 区分、嵌套结构、异常类型、畸形 JSON 和输出伪造字段。
- 未完成分母、基础设施失败停止、模拟不能升格为真实报告。
- 公私字段注入、示例顺序、组间逐字节一致、首轮与第二轮消息组成。
- 4096/4097 输入、256/257 回答、终止 token、模板不一致、
  解码再编码增量及超限拒绝，均由 tokenizer 替身构造可重复边界例。
- 导入纯净性：无 task `exec`、无模型/tokenizer 自动加载、无 subprocess、
  网络或安装副作用；既有 26 项 CPU 测试保持通过。

以后实际执行题目之前，单独选择并审查一个隔离后端，冻结镜像/根文件系统、
实际运行时身份、只读输入、无凭据/无网络/无管理接口、CPU/内存/进程/
磁盘/输出/全流程时限和本任务资源清理。先通过有界隔离探针，再启动题库。
当前不选择产品、不承诺现有远程服务合格，也不写一个普通宿主后备执行路径。
后端的数值预算及安全版本审查属于该独立启动方案，不是本地纯函数验收。

真实 tokenizer 检查与隔离执行是两个不同关口，可以分别通过；
任何一个通过都不使另一项自动合格，更不授权训练。
