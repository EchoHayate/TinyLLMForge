## 2. C04：按全局下一条结束事件截断本事务

正确题意仍为交错的独立事务。新故障不维护错误的活跃事务栈，而是从每个
begin回看其后日志，错误地认为“接下来第一条commit/rollback就结束本次begin”，
漏掉终止事件的事务ID条件。

拟议初始算法完整定义：

1. 按输入索引顺序枚举每个begin事件，记下begin索引和该事件的事务ID。
2. 对本次begin，从其后第一个位置开始，按原顺序找全局第一条
   commit或rollback；**不要求该结束事件的ID等于本begin的ID**。
3. 如果找到的是rollback，结束本次begin的扫描，不输出任何记录。
4. 如果找到的是commit，只累加begin与该结束位置之间、操作为add且ID等于
   本begin ID的amount；金额求和的ID过滤已经正确，不再叠加金额归属bug。
5. 为这个错误配对存一条`结束位置、本begin的ID、所求总额`记录；
   随后也结束本次begin的扫描。
6. 未找到任何结束事件的begin不输出；内部遇到别的begin本身不截断扫描。
7. 处理全部begin后，按保存的结束位置升序稳定排序。若错误配对造成同一
   结束位置有多条输出，保持这些begin的原枚举顺序，不额外按标签破同分。
8. 丢掉位置字段，返回`[本begin的ID, 总额]`列表。

单一根因：缺少生命周期终止边界的所有者条件。begin重用、金额求和、
rollback不输出、EOF未结束不输出都没有额外独立故障；它们的错误结果
来自把生命周期绑定到其他事务的结束事件。

它借用既有参考B的逐生命周期分解，但不重写B或声称新的独立参考创作。
正确参考B的默认tuple排序在合法匹配下结束位置互异；本初始算法明确使用
仅结束位置的稳定排序，避免让错误配对后的并列标签排序引入含糊。

必要修复：只让同ID的commit/rollback截断当前begin，其余事务的结束事件
必须继续扫描，而非先break后禁止输出。合法域保证同ID下一次begin不可能
出现在该生命周期结束前；加上所有者过滤后首次同ID结束就是本生命周期。
内部同ID add求和已正确，最后按实际commit位置排序还原跨事务提交次序。
可以采用其他全域等价实现，不强制保留扫描算法或特定补丁。

## 3. P01见证和局部补丁反证

原P01事件索引：

| 索引 | 事件 |
| --- | --- |
| 0 | begin a |
| 1 | begin b |
| 2 | add a 5 |
| 3 | add b 2 |
| 4 | rollback a |
| 5 | begin a |
| 6 | commit a |
| 7 | commit b |

错误扫描：

- begin a(0)看到rollback a(4)，不输出，恰好正确。
- begin b(1)也看到rollback a(4)，错误地停止，丢掉b本应在7处提交的2。
- begin a(5)看到commit a(6)，输出a0。

预测错误返回`[["a",0]]`，正确返回保持`[["a",0],["b",2]]`。
未来initial的具名拒绝见证仍是公开P01，不借助新增私有例。

以下并非新评分变体，只是澄清最小修复：

- 所有求和本来就从零开始；增加begin归零不能补回被外来rollback截断的b。
- 仍在任何结束事件break、仅在输出前检查ID，也会在P01丢掉b，不能修复。
- 只修commit的所有者条件、不修rollback，P01仍丢b。
- 只修rollback的所有者条件、不修commit，会在H06错误输出从未提交的b9。
- 只把输出标签换成结束事件ID，仍不能补回P01被外来rollback丢掉的b。

R1的“目标记录移到栈尾”补丁不再有可直接作用的活跃记录栈；这里的输入
是带原始时间索引的日志扫描，不能把记录重排与历史结束位置混为一谈。
输入副本仍允许修改，完整按ID分组并保留原始提交位置也是合法替代实现；
不据此禁止重排。它不是在现有尾部更新/弹出前加一次C10刷新就能修好的程序。

| case | R2 C04 initial 的手推返回 | 原正确值/依据 |
| --- | --- | --- |
| P01 | `[["a",0]]` | 正确a0/b2；b被外来rollback提前截断 |

| H05 | `[["a",1],["b",2],["c",3]]` | 三次begin均错误绑定首次commit b，同结束位置稳定按begin顺序；正确顺序是b2/a1/c3 |

二者分别补充P01对外来rollback的观察，不新增参数或期待值。

保留原两个错误变体及见证不变。仅P01就足以区分三份：

- R2 initial：`[["a",0]]`。
- 原variant_1（终止清全部）：`[["a",0],["b",0]]`。

以上都是手推值；没有创建或调用新函数。C01的八条预测继承R1，总计仍为
两题16条设计预测，后续须与实际源码逐条重新核对，不作为执行回执。

## 5. C04相关23对的替代提案

M/D含义继承R1；全部是待独立复核的设计判定，不是已经准入或独立性证明。
初始错误只有一个所有者条件缺失，小补丁本身不构成拒绝理由；应比较该条件
控制的生命周期边界及具体旧题修法，而非按改动行数决定。

| 对象 | 提案 | 具体最小修复比较 |
| --- | --- | --- |
| S01 | D | 时间等号已有且无关；需让外来终止事件继续扫描 |
| S02 | D | 不是交长算式去掉加一，金额求和端点已经排除begin/终止位置 |
| S03 | M | 生命周期边界共享；累计和本已从零计算，缺的是正确匹配同ID结束 |
| S04 | M | 作用域共享；每begin的局部结果已独立，清seen/清总额不能恢复被外来结束截断的范围 |
| S05 | D | 单生命周期金额总和不是两袋最小频次 |
| S06 | D | 添加耗券不能匹配生命周期结束对象 |
| S07 | D | 不是分数并列的等号；最终排序输入的结束位置本来就被错绑定 |
| S08 | D | 输出排序必须保留；去掉最终排序会在正确交错事务上破坏提交次序 |
| D01 | D | 不涉及整数符号分支 |
| D02 | D | 不是固定起点切片；正确结束取决于ID和终止操作 |
| D03 | M | 所有者选择共享；这是在历史扫描中拒绝外来边界，非替换一次字典外层key |
| D04 | D | 单字符独立计数无生命周期跨度及提前break |
| C01 | M | 都决定历史有效范围；时间清理晚于读取与错误配对另一个ID结束不同 |
| C02 | M | 都排除无关记录的影响；control不推进逻辑地址与外来终止不能截断生命周期不是同一既有补丁 |
| C03 | D | 几何区间裁剪不能决定事件所有者 |
| C05 | M | 按键生命周期共享；C05在当前reset删本键状态，这里查找同ID结束边界，不能补pop解决 |
| C06 | M | 生命周期范围共享；内层保峰不能修复日志结束事件误配 |
| C07 | M | 事务约束共享；库存试扣原子性不同于配对日志begin/end |
| C08 | D | 去除同来源重复只改变票数单位，不修错误终止配对 |
| C09 | D | 保留重复索引不同于识别同ID的终止事件 |
| C10 | M | 顺序/身份共享，但R1尾部操作脚手架已不存在；需匹配历史结束位置，不是当前访问移到最新端 |
| C11 | M | 过滤有效证据共享；其计数谓词已正确，只修first门控不能恢复本题被截断的生命周期范围 |
| C12 | D | 本题按提交位置排序已实现但位置错误，重新按priority消耗配额不能修复 |

C01:C04在此表只计一次；不再另外加一条到总数。其余22对直接引用R1，
