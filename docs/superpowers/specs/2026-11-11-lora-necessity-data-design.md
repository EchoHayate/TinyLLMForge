## 1. 本阶段要交付什么

交付可用于后续训练和评测的具体小函数修复题、明确规格、正确实现、
可见测试、独立评分测试及答案核验记录。不加载模型或分词器，不训练，
不连接远端，不运行候选源码，不安装，不提交或推送，不改旧实验或主引擎。

“具体任务”不等于真实业务数据：本批是助手原创的受限程序修复题，
不是生产缺陷采样，也不声称预训练未见。44 道题不支持生产效果外推。
本阶段不会把 CPU 计分器的人工结果换成“真实”标签。

分两步验收：

1. 确认本草案后，按固定结构编写题目、答案及核验材料，完成静态交叉审阅。
2. 对已审阅参考实现与错误变体做动态核验，必须另有经过审查的执行边界。
   当前不在宿主直接 `exec`/导入题库源码。静态阅读不能冒充动态通过。

模型分词器长度检查另行实施；未完成之前不能宣称数据已可启动训练。

## 2. 数据构建选择

| 方案 | 优点 | 风险与本轮选择 |
| --- | --- | --- |
| 独立编写、先固定结构、再交叉核验 | 可控制监督与迁移的关系，能逐条解释答案 | 推荐；必须披露助手构建与人工签核缺失 |
| 复用旧选择实验及其变体 | 准备快 | 不采用；旧样本不能成为新的未见评测，固定选项也不是函数修复 |
| 大批量模板生成后筛选 | 数量多、实现方便 | 不采用；容易只有表面差别，也容易按模型结果挑题 |

不以“哪个题目更能让 LoRA 赢”作为收录标准。本轮不调用待测模型挑题、
调难度或核定答案。开发校准失败时按上位设计停止，不拿迁移结果反向调题。

## 3. 家族与输入输出约定

监督和迁移共享四个主要修复机制：

- `bounds`：错误的端点或区间包含关系。
- `reset`：局部状态没有在规定作用域边界重置。
- `multiplicity`：把出现次数错误压成存在/不存在。
- `order`：丢失规格要求的稳定顺序或并列规则。

保留集合使用另外四个主要机制：

- `signed_rounding`：有符号整数的舍入或余数定义。
- `matrix_axis`：矩形数据的行列映射。
- `escape_scan`：转义字符与普通字符的扫描状态。
- `validation`：规格要求的输入拒绝规则。

这是主要缺陷标签，不是互不相交的能力分类。例如矩阵也有边界，
字符串扫描也使用状态。必须审查真正需要的修复，不以标签不同证明没有迁移。
开发集合每题一个独立家族，不强加其与监督家族相同的额外约束。

通用约定：

- 每题只导出一个确定性 Python 函数，不依赖文件、网络、时钟、随机数或导入。
- 使用整数、ASCII 字符串、布尔值、null 及其列表；字典只承载固定字段。
- 具体题面逐条规定空输入、重复值、负数、并列、索引与端点语义；
  不适用的条件写明不在输入域内，不能由参考实现临时决定。
- 不使用浮点近似比较；非法输入题明确要求 `ValueError`，不按异常消息判分。
- 普通有效输入长度不超过 32；整数绝对值不超过 1000。每题可进一步收窄。
  输入域上界写入题面。无输入修改要求，候选可读参数的隔离副本。
- 模型任务是修复功能，不限制必须按某个补丁修改；不比较源码与参考答案的相似度。
- 函数命名与参数不使用单字母；参考答案需要在未来的 256 输出 token 上限内
  实测容纳，当前不以字符数估算代替。

### 4.1 监督：8 项，每家族 2 项

| ID | 家族 | 函数意图与结构 | 必须出现的失败见证 |
| --- | --- | --- | --- |
| S01 | bounds | 有序时间列表中严格早于截止点的前缀长度；顺序扫描 | 存在恰好等于截止点的时间 |
| S02 | bounds | 两个半开整数区间的交集长度；端点公式 | 区间仅在端点相接 |
| S03 | reset | 按分隔值切段，输出各段总和；段累积器 | 至少两个非空段，第二段不能继承第一段和 |
| S04 | reset | 判断每一行是否内部无重复；逐行集合 | 同值跨行出现但各自行内无重复 |
| S05 | multiplicity | 两个整数袋的交集大小；频次最小值求和 | 同一值在两个袋中均重复且次数不同 |
| S06 | multiplicity | 字符库存能否满足一个词；按需求扣减 | 字符都存在但某字符库存次数不足 |
| S07 | order | 最高分记录的最早索引；并列更新规则 | 最高分出现两次 |
| S08 | order | 标签去重并保留首次出现顺序；输出构建 | 非排序顺序的重复标签 |

### 4.2 开发：4 项，每家族 1 项

仅用于 base/text 的协议与难度预警，不用于更新参数或主分数。

| ID | 家族 | 函数意图与结构 | 必须出现的失败见证 |
| --- | --- | --- | --- |
| D01 | dev_sign | 返回整数符号 -1/0/1；互斥分支 | 零不能落入正数或负数分支 |
| D02 | dev_stride | 从给定起点每隔固定正步长取元素；索引步进 | 起点非零且步长大于一 |
| D03 | dev_nested_lookup | 在固定两层字典查键，缺失返回 null；逐层读取 | 内外层键名不同且同名旁支存在 |
| D04 | dev_count_predicate | 统计 ASCII 字符串中的数字字符；分类扫描 | 字母、数字和标点混合 |

### 4.3 迁移：16 项，每家族 4 项

| ID | 家族 | 函数意图与结构 | 与同家族监督不同的关键结构 |
| --- | --- | --- | --- |
| T01 | bounds | 给定网格单元，输出网格内的四向邻居坐标 | 二维候选坐标裁剪，不是前缀计数或区间交集 |
| T02 | bounds | 输出序列中所有完整定长窗口的起点 | 按长度生成有效索引，不比较时间截止点 |
| T03 | bounds | 判断非空整数闭区间是否全部被另一个闭区间覆盖 | 包含谓词和闭端点，不求半开交集长度 |
| T04 | bounds | 枚举环形缓冲区逻辑区间占用的物理索引 | 跨容量尾部回绕；不是有序阈值扫描 |
| T05 | reset | 对成功/失败事件流，输出每次事件后是否达到连续失败阈值；成功清零 | 成功事件触发连续计数重置，不是按行集合或分段求和 |
| T06 | reset | 将带批次结束标记的事件流分批编号，批内索引从零开始 | 双层编号状态，不是段求和 |
| T07 | reset | 在行内解析连续 ASCII 数字为整数；遇非数字结束当前数 | 数字构建与终止状态，不按固定分隔值求段和 |
| T08 | reset | 输出每个用户会话内相邻时间差；用户改变开启新会话 | 前值状态和首项省略，不是集合或累积和 |
| T09 | multiplicity | 跳过并截取游程编码序列，保留各段重复数量 | 起止点位于游程内部；不是补回一次库存删除 |
| T10 | multiplicity | 最少删掉多少元素能让两个袋相等 | 双边频次差绝对值和，不求交集大小 |
| T11 | multiplicity | 计算不同索引的无序等值元素对数量 | 频次组合数，不能仅统计重复值种类 |
| T12 | multiplicity | 按排序后的值输出其可组成的完整三元组个数 | 频次整除，余量不得凑到其他值 |
| T13 | order | 对记录按分数降序排列，同分按输入顺序 | 稳定全排序，不是取单一最优索引 |
| T14 | order | 两路有序事件合并，同时间优先左路且保留路内顺序 | 双指针合并，不是单列表去重 |
| T15 | order | 根据最后一次出现的先后顺序输出不同标签 | 末次位置排序，区别于 S08 首次顺序 |
| T16 | order | 整数按负数/非负数稳定分区，保留重复项 | 初始交换算法破坏相对顺序；不是删除最终排序 |

### 4.4 保留：16 项，每家族 4 项

| ID | 家族 | 函数意图与结构 | 必须覆盖的边界 |
| --- | --- | --- | --- |
| R01 | signed_rounding | 整数除以正整数后向零截断；不得转浮点 | 负数不能整除与零 |
| R02 | signed_rounding | 整数除以正整数后向正无穷取整 | 正负非整除、整除 |
| R03 | signed_rounding | 给出向零商对应的余数，商余重建被除数 | 负余数与零余数 |
| R04 | signed_rounding | 舍入到最近的正整数倍，距离相等时远离零 | 正负中点与非中点 |
| R05 | matrix_axis | 非空矩形矩阵转置 | 行数列数不同，单行 |
| R06 | matrix_axis | 矩形矩阵按列求和 | 不同列有不同和值 |
| R07 | matrix_axis | 非空矩形矩阵顺时针旋转九十度 | 非方阵与单列 |
| R08 | matrix_axis | 将平坦数组按指定行列数还原为行优先矩阵 | 行列不同，位置不能对调 |
| R09 | escape_scan | 按未转义逗号分隔；反斜杠转义紧随其后的任意字符 | 被转义逗号、反斜杠对、末尾反斜杠拒绝 |
| R10 | escape_scan | 解码只允许 `\\n`、`\\t`、`\\\\` 的文本 | 连续转义、普通字符、未知或残缺转义拒绝 |
| R11 | escape_scan | 给反斜杠和双引号加转义，其余字符原样 | 相邻特殊字符不能重复转义新插入字符 |
| R12 | escape_scan | 找到文本中首个未被反斜杠转义的双引号索引 | 偶数和奇数个前导反斜杠，未找到返回 -1 |
| R13 | validation | 接受 0 到 100 的严格整数，否则抛 ValueError | bool、字符串、null、上下界外拒绝 |
| R14 | validation | 接受非空且每行等长的二维整数列表，返回形状 | 空行、不齐行、非列表行拒绝 |
| R15 | validation | 验证恰好四位的 ASCII 十进制代码并返回整数 | 前导零允许，长度与非 ASCII 数字拒绝 |
| R16 | validation | 验证闭整数区间的端点类型与顺序，返回整数点数 | 相等端点有效，倒置与 bool 端点拒绝 |

## 5. 题目包与权限分层

后续实现的新文件只放在 `experiments/lora_necessity/` 下，与旧样本分离：

- `data/structure_v1.json`：确认后的结构表、版本与选择理由。
- `data/supervision_v1.json`：S01–S08 的规格、初始函数、可信失败见证、
  可见测试和完整正确实现，组成唯一的八例监督源。
- `data/prompts_v1.json`：D/T/R 的公开字段；没有参考答案、评分输入或预期结果。
- `data/oracles_v1.json`：D/T/R 的参考源码、独立评分用例、错误变体与推导说明。
- `data/task_sources_v1.json`：离线构建源，包含全部 44 项的上述材料，包括
  监督题不应进入训练文本的评分测试和错误变体；不允许作为模型输入文件。
- `data/review_v1.json`：每项答案、结构重复和错误变体审查结论及证据身份。
- `data/manifest_v1.json`：绑定上述内容的摘要，以及兼容现有 `build_manifest`
  的 44 行元数据。不能用 ID 的摘要冒充内容摘要。
- `DATA_AUDIT.md`：报告哪些检查已经发生、哪些尚未发生。

这些是拟定接口，不是已存在文件。本次只准备数据，不引入生产构建器或
提示构建器；派生 JSON 通过一次性、只处理数据的本地转换生成。
数据构建器、提示构建器和动态执行器应有
各自独立计划，不能为了得到一个“PASS”在数据工具里顺便执行源码。

训练器只能读八例监督源；text 与 lora_text 的示例段使用同一确定性渲染，
逐字节比对并记录摘要。评测任务的公开字段四组一致。显式 allowlist 选择字段，
不能把整条 oracle 字典传入模板后靠“当前模板没用它”避免泄漏。

分文件只是数据组织，不是安全隔离证明。执行阶段不挂载 oracle 目录给候选；
评分测试由受信控制端逐例驱动。真正的文件权限、网络与进程隔离另行验证。

## 6. 怎么核验“答案确实对”

每题必须形成一份能被第二名审阅者复核的记录：

1. **规格**：给出输入域、输出、边界、异常和并列规则，不能只说“修复 bug”。
2. **见证**：至少一个公开用例能区分错误实现与正确行为；写出逐步推导，
   不是把参考函数运行结果抄为期望值。
3. **用例**：至少 2 个公开用例和 6 个不同的评分用例，覆盖普通与适用边界。
   公开与评分输入不重复；六例是最低检查量，不是完备性保证。
4. **变体**：除原始错误实现外，至少两个行为不同的错误变体；
   每个都有一个固定评分用例能拒绝它。不能只改名字制造“杀死更多变体”。
5. **交叉审阅**：另一名审阅者从规格推导期望值，再对照参考答案；
   明确是否使用同一模型，不能把第二个 agent 称为独立人工签核。
6. **动态核验**：通过另行审查的执行器接受正确实现、拒绝上述错误变体，
   记录输入、输出、异常、超时和源码摘要。当前阶段此项保持未执行。

遇到规格含糊、参考实现与手算冲突或变体未被拒绝，整题暂不准入；
若题库不满固定 44 题，整批不可运行。不静默删题或在发现模型成绩后替换。
手工推导、不同实现与多个测试仍可能共同出错；最终只声称
“经所列检查的受限测试正确性”，不声称所有输入已证明正确。

## 7. 防止结构泄漏与结果反向调参

- 编写前确认结构表；编写后复核监督对迁移的所有 8×16 对关系。
- 审查错误实现、参考算法、控制流与数据结构，记录差异；
  对家族内相近项尤其是 S03/T06、S05/T10、S06/T09、S08/T15 做专项检查。
- 名称/常量归一化和 AST 相似性可作为报警，不能自动判定结构独立。
  若只是把循环包一层、换字段或改常量，退回，不用唯一 template_id 放行。
- 也检查开发与监督/评测之间的重复，以及保留题的实际主要缺陷是否错标。
- 在模型运行前固定题库、提示和评分规则；读取代码与手算核验属于题库构建，
  不是“密封测试无人看过”。不能声称构建者对题目盲测。
- 任何根据模型分数做的改动都把本批降级为开发数据，后续需新题复验。

## 8. 长度、冻结与验收

八例完整文本记忆是不可删减的共同输入。未来必须用经核验的实际 tokenizer
和 chat template 检查训练样本、四组首轮输入、第二轮反馈输入，以及参考答案。
第二轮还包含首轮最多 256 个输出 token 和固定格式反馈，不能只检查题面。
若超过 4096 输入或参考答案超过 256 输出 token，冻结前统一压缩题面；
不得只删 text 的示例。冻结后发现超限直接停止并登记新版本，不静默截断。

本轮没有 tokenizer 加载许可，长度状态必须为未验证；不能靠估算标为通过。
静态内容草案、参考答案动态核验通过、长度通过与准入运行是不同状态，
分别记录，不使用一个总 `ready=true` 混淆。

本阶段通过条件是：结构设计确认，44 题文本与审核材料齐全，静态交叉审阅无
未解决歧义，公开/监督/oracle 字段隔离检查通过，内容摘要绑定真实字节。
尚未运行的动态核验和分词器检查必须明确列为后续阻断项。
没有人工签核时，继续使用“助手构建的受限试验题库”名称。

`benchmark_eligible`、`formal_evaluation_ready`、`net_benefit_established`、
`isolated` 保持 false。本阶段不产生 LoRA 优劣、训练成功或生产就绪结论。
