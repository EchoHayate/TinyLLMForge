# 参数更新是否有必要：可信监督 LoRA 最小试验

日期：2026-11-10。

状态：**用户已批准设计并继续本地实施；不是训练或远程启动许可。**

用户批准推进“先验证参数路线是否有必要”的建议。本文件把建议收敛为一项
可停止的小样本试验；随后用户以“可以，继续吧”批准本方案进入实施。
本地实施先覆盖数据与纯 CPU 协议，再分别审查训练 worker 和隔离评测。
不修改主引擎、加载模型、训练、安装、连接远端、运行生成代码、提交或推送。
旧 selection comparison 不随本设计自动启动。

## 1. 唯一研究问题

在同样的可信纠错示例、工具权限和推理调用上限下，少量梯度 LoRA 更新，
能否比仅保留文本示例，更好地修复未用于更新的小函数，同时不破坏旧任务？

本轮不是 RSI 验证，不研究自行判断反馈真假，也不研究每个 token 更新权重。
允许结论是“当前参数方案不值得继续”。未通过不证明全部 LoRA 方法不可能。

已有 SHINE 实验是冻结超网络生成适配器，没有训练；其换问法诊断为
44/48 supported，对应原文参考为 48/48。已有在线反馈选择实验不更新权重，
也不能为本轮提供参数学习成功的证据。旧样本不能作为本轮未见任务。

## 2. 三条路线与建议

| 路线 | 能回答的问题 | 取舍 |
| --- | --- | --- |
| 梯度 LoRA，推荐 | 经监督的参数更新是否带来额外迁移收益 | 需要训练路径和独立评测，但直接检验用户关心的命题 |
| 继续冻结 SHINE | 上下文编码是否更可靠、可摊销 | 不检验梯度学习，当前短事实结果不足以支持扩大 |
| 只继续无权重选择诊断 | 模型是否使用反馈、是否受标签/位置影响 | 可澄清旧实验，但不能替代参数方法试验 |

本轮选择第一条，不同时训练超网络，不搜索多个 LoRA 配置。
单次适应发生在评测之前；评测时冻结适配器，每个问题从新的 KV 状态开始。

## 3. 数据与判定对象

任务仍沿用已讨论的小函数代码修复，不改成固定 A/B/C 选择、事实记忆或输出
格式恢复。任务给出明确规格、初始函数和公开测试，要求返回一个完整函数。

拟定一个开发筛选批次：

- 8 个可信监督示例：4 个修复机制家族，每家族 2 个。
- 4 个协议开发任务：与监督/评测模板分离，只检查提示、解析、执行及难度。
- 16 个迁移任务：对应上述 4 个机制家族，每家族 4 个新函数。
- 16 个保留任务：来自另外 4 个未参与适应的家族，每家族 4 个。

先冻结机制家族与结构模板的划分，再编写具体题目；同机制内允许迁移，但不能
只改变量名、常量或题面。人工审查跨集合结构重复。保留任务指适应前已有
能力的测量集合，不是假定基础模型必然答对；全部任务保留在分母内。

每个监督示例包含规格、错误实现、可信失败见证、正确实现。每个任务的规格、
参考实现、可见测试和评分测试由第二名审阅者交叉核对；没有独立人工签核时
明确标为助手构建的受限试验，不称权威 benchmark。参考实现不得与候选共用
修复逻辑；准备正确实现及已知错误变体，验证评分器能接受前者、拒绝后者。

评分按完整函数在固定测试下的功能通过判断，不按回答全文字符串匹配，
不由生成答案的模型自行评分。有限测试通过不等于对所有输入正确。

## 4. 四个对照组

| 组别 | 适配器 | 推理时看到的历史示例 |
| --- | --- | --- |
| base | 无 | 无 |
| text | 无 | 完整相同的 8 个可信监督示例 |
| lora | 训练后的固定适配器 | 无 |
| lora_text | 与 lora 完全相同的适配器 | 与 text 逐字节相同的 8 个示例 |

主要比较是 lora_text 对 text，隔离同一推理信息下参数更新的增量；
lora 对 text 是用参数替代文本的辅助比较；base 测量没有适应的表现。
四组都获得当前任务的相同规格、初始函数、可见测试和工具权限。
不限制 text 保存示例来人为制造 LoRA 优势。

每任务每组最多两次模型调用：先给出候选，再接受一次固定可见测试反馈，
然后给出最终候选。不因首轮通过就提前省略第二次调用；统一两阶段
便于配对，首轮非法结果返回固定类型错误反馈。第二轮仍失败则计失败。
可见核验每组每题恰好一次机会；无法解析的候选返回固定错误反馈，记录为未
执行，不能伪造工具执行次数。最终评分不回传。任何执行都必须经过第 7 节准入。
生成仅允许函数源码，不包含 Markdown 或额外解释；解析规则事先固定。

4 个协议任务只运行 base/text，共最多 16 次生成；
32 个迁移/保留任务的四组共最多 256 次生成，总上限 272 次。
协议任务不参与主结果。不把原样保留初始函数的失败当作新修复成功。

这提供相同的推理调用上限和工具机会，不声称总算力相同：
LoRA 的额外训练成本必须单列。若 text 已解决问题，不自动追加重试来
寻找参数优势；后续等总预算研究须独立设计。

## 5. 拟定唯一训练配置

使用既有 Qwen3-8B 的经核验 checkpoint，不改基础模型权重，不量化，不加载
SHINE。以下为拟议配置，必须在实现前验证底座结构和既有依赖能支持：

- 所有 decoder 层的 q_proj/v_proj 使用 rank 8、alpha 16、dropout 0。
- 一侧因子随机初始化，另一侧为零，初始有效增量为零；seed 42。
- 基础权重冻结；仅 LoRA 参数进入优化器。BF16 基础前向，LoRA 参数 FP32。
- AdamW，学习率 5e-5，weight decay 0，梯度范数裁剪 1。
- batch size 1、梯度累积 1，8 个示例固定顺序重复两遍，共 16 个更新步。
- 仅对正确修复的回答 token（包括终止 token）计算交叉熵；
  规格、错误实现、示例说明与 padding 均不参与 loss。
- 保存初始与第 16 步状态，不按评测分数挑 checkpoint，不扫描学习率/rank。

训练和推理均不静默截断。所有组输入上限 4096 token，每次回答上限
256 新 token；完整文本示例必须在此限制内。数据冻结前检验长度；冻结后
发现超限即停止，不能只删 text 的示例。固定 greedy 和同一 chat template。

CPU 测试先验证标签屏蔽、参数白名单、状态重置与成本记录；真实训练后核对
基础权重身份未变、只有批准的 LoRA 张量更新、有限 loss/梯度，以及无更新
对照的有效增量为零。loss 下降仅是训练路径信号，不是任务收益。
非有限数值、越界或结构不匹配直接停止，不自动更换配置或安装依赖。

## 6. 防止看到答案后继续优化

监督/协议开发材料与迁移/保留评分材料分别冻结。最终实现、提示、适配器、
样本次序及评分器均在打开评测输出前固定并绑定摘要。

协议开发阶段只有 base/text，没有用 LoRA 结果挑任务。若协议解析/执行
失败，或 4 道任务两组都全部通过/都全部失败，本批次标记为校准不足并停止；
不得声称不存在能力或不存在收益。这只是小样本预警，不证明难度校准充分。

评测输出不能回到训练器。若根据本批次结果调整任何方法，当前迁移/保留集合
即降级为开发材料；下一次结论必须用新的冻结任务，不能重复称独立评测。
这一批本身始终是开发筛选，不是最终保留集或统计确认实验。

## 7. 执行与状态边界

这是独立实验，不接入 TinyLLMForge scheduler、KV cache、CUDA Graph 或服务
请求热更新。一次离线训练后冻结状态，按轮换组序配对推理，不在线累计更新。
各题无历史 KV；各组不能共享可写适配器/优化器状态或候选执行目录。

生成代码不是已审阅的固定函数，不得复用旧宿主固定程序执行器来直接运行。
候选执行器必须有已验证的文件系统、网络、凭据、CPU/内存/进程/时限隔离，
禁止接触监督答案、隐藏评分数据和宿主控制状态。评分测试由受信控制端驱动，
不得把整个答案目录作为候选可读文件挂入。具体隔离实现必须另行审查。
历史环境报告不是今日准入证据；若无合格执行环境，在候选执行前停止，
不通过加大宿主权限或静态 import 黑名单代替隔离。

设计批准后先完成数据与纯 CPU 实现/审查，再申请单独有界运行。
拟定真实批次上限为 1 个专属获准 GPU、3600 秒完整流程墙钟、16 个训练步、
272 次生成，不重试、不增卡、不自动续时；清理时间在墙钟内预留。
这些是预算上限，不是本轮能够跑完或能放入显存的承诺。
启动前必须核验设备归属、精确运行环境、显存预算和完成/清理余量；
不足则不启动，执行中触顶记不完整，不悄悄减少样本或输出长度。

## 8. 筛选门槛与停止规则

每组报告迁移/保留各 16 个固定分母；同时报告配对的“对变错”和“错变对”、
超时/非法输出、逐家族结果和未完成项。不把多个测试用例当独立任务样本。

拟议的开发筛选门槛，不是普适有效性阈值：

1. lora_text 对 text 在迁移集合至少净增加 2 个通过任务（12.5 个百分点）。
2. 保留集合中，text 通过而 lora_text 失败的任务必须为 0。
3. 参数完整性、隔离、全部运行收据和成本记录通过，无遗漏样本。

满足三项仅标为 `PROMISING_FOR_REPLICATION`，需新的独立任务与训练种子复核；
16 题和一个训练种子不建立统计显著性、长期稳定性或生产可用性。
完整有效且校准通过时，保留集合出现至少一项 text 通过而 lora_text 未通过，
记 `OBSERVED_REGRESSION`；没有这种保留任务退化但迁移净增小于 2（包括负值），
记 `NO_GAIN_IN_THIS_PILOT`。迁移集合的负值和逐项改坏数必须原样报告，
不能用“没有增益”的标签掩盖变差，也不修改原定的保留任务零退化门槛。
若缺失/超时导致完整比较不成立，标记
`INCONCLUSIVE_INCOMPLETE`；执行/参考答案问题则标记 `INVALID_PROTOCOL`。
缺失的预定记录仍计任务失败，但不据此给出算法胜负结论。

lora 的辅助成绩不能替换未通过的主要比较。若辅助结果支持省 token 的假设，
只登记为后续独立成本实验的依据，不事后更换本轮验收目标。
即使达到筛选门槛，也不能进入主引擎或错误反馈闭环；需要复核收益和遗忘。

## 9. 成本与“值得”的边界

分别记录模型加载、训练、示例整理/核验、适配器保存/加载、生成、工具执行、
最终评分、清理的时间；同时记录输入/输出 token、模型/工具调用数、
峰值 allocated/reserved、适配器/优化器/文本状态字节和总墙钟。
未知项保留未知，不当作零；不重复累加包含关系，不以生成时间替代总成本。

共享训练成本在各 LoRA 组单独评估部署价值时各计一次，不随组数摊半。
保留任务是诊断成本，不自动算作未来业务复用收益。训练示例数量也不是复用数。
本轮报告效果—成本的实测取舍，不指定未来请求量来制造摊销优势。
没有同质量或明确可接受的质量—成本取舍，就保持 `net_benefit_established=false`。
