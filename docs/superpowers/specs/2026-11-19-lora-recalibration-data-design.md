## 1. 目标与选择

目标不是保证 LoRA 赢，而是准备一组有明确答案、能揭示真实功能错误的
开发题；之后才判断这些题对当前模型是否有区分度。

- 采用已讨论的方案：12 题、base/text 两种记忆条件，每个条件共用一份
  首轮候选，再分别进行真实反馈续答与无结果续答。
- 不采用仅增加复杂题但没有续答对照的方案，否则无法区分反馈与额外推理。
- 不扩展到完整仓库修复，不搜索题池，不按待测模型的失败率选择题目。

LoRA 参数更新的增量仍需将来比较 `lora_text` 与 `text`；本阶段的反馈
诊断不代替它。开发题不用于训练，也不作为之后的独立收益评测题。
已有真实训练链路通过与旧四题满分结果均保留，不重跑、不改标签。

本轮落实结构、精确语义、24 个公开示例的手工推导，以及后续参考实现和
反例的核验要求。六个私有评分输入、初始程序与参考/变体源码尚未编写，
不能把下面的覆盖要求称为已完成的 96 条用例。

## 2. 公共输入和比较契约

- 每题一个确定性 Python 函数，不允许导入、文件、网络、时间或随机性依赖。
- 整数均为严格整数，不含 bool；除逐题收窄外，范围为 [-1000,1000]。
- 标签均为长度 1..16、仅含 ASCII 小写字母的字符串。没有 Unicode 排序问题。
- 每个列表长 0..32；逐题的总长度限制额外生效。固定形状的列表表示记录，
  不接受缺字段、额外字段或类型混用。只测合法输入，不隐含输入拒绝能力。
- 上述大小界限约束输入，不直接套给输出。例如 C06 的 32 个结束标记会
  产生 33 个空组，C09 的配对总数可达 1024；均是合法返回值。
- 候选拿到输入的隔离副本，不增加“不得修改输入”的评分条件。
- 比较返回值的 JSON 类型与完整结构：整数、布尔值和 null 不可互相充当。
  顺序严格匹配；不靠集合化或排序掩盖顺序错误。没有预期异常的有效用例。
- 每题最终恰好 P01/P02 两条公开用例、H01–H06 六条私有用例，同题八份
  完整参数不得重复；私有用例不是公开输入换一个 case ID。
- 下述 P01/P02 是可公开的设计示例。其期望值为手工推导，不是运行结果。
  H01–H06 只固定覆盖意图，后续先写输入与逐步推导，再写参考实现。
- 一题八例仅是有限功能检查，不是完备正确性证明，也不保证模型会犯错。

## 3. 十二题的明确语义

### C01 / bounds：带过期时间的容量预订

接口：`admit_reservations(capacity, requests)`。

`capacity` 为 0..32；每条请求为 `[time, size, expires]`，time 为
0..999 且非递减，size 为 1..32，`time < expires <= 1000`。
按输入次序处理，即使 time 相同也不合并。每次先移除所有
`expires <= time` 的已获准请求，再判断已占用量加 size 是否不大于容量；
获准才占用容量。拒绝不影响后续状态。返回逐请求的布尔值。

- P01：参数 `[2, [[0,2,2],[1,1,4],[2,2,3],[2,1,4],[3,1,4]]]`，
  期望 `[true,false,true,false,true]`。时刻 2 先释放首笔，时刻 3 再释放
  第三笔；两笔被拒绝的请求均没有留下占用。
- P02：参数 `[0, [[0,1,1]]]`，期望 `[false]`；零容量不是无限容量。
- H01–H06：空请求；同刻多笔恰好装满；多笔同刻过期；单笔超过总容量；
  拒绝后有较小请求成功；过期边界与拒绝状态共同作用。
- 参考分解：一份维护活动请求；另一份按历史已获准请求重新求当前占用。
- 缺陷目标：初始程序只在 `expires < time` 释放；变体拒绝恰好满容量；
  另一变体把拒绝请求也写入活动集合。

### C02 / bounds：带控制段的逻辑区间覆盖

接口：`logical_block_coverage(blocks, start, count)`。

每个 block 为 `["data",length]` 或 `["control",length]`，length 为
0..32，所有 data 长度之和不超过 32。start/count 为 0..32。
只有 data 占用逻辑地址；control 无论长度多少都不推进地址。
返回每个 data 块与半开查询 `[start,start+count)` 的交集长度，按块输入
次序，包括长度为零或无交集的数据块；control 不产生输出位置。
查询可超出数据末尾，不补造数据。

- P01：参数 `[[["data",2],["control",9],["data",3],["data",0]],2,2]`，
  期望 `[0,2,0]`。三个数据块分别占 `[0,2)`、`[2,5)`、`[5,5)`。
- P02：参数 `[[],3,4]`，期望 `[]`。
- H01–H06：只有控制段；零 count；查询越过末尾；零长度块夹在数据中；
  起止点跨越多个数据块；大控制长度与恰好相接端点共同出现。
- 参考分解：累积地址后求交；逐个逻辑字节确定所属数据块并计数。
- 缺陷目标：初始程序让 control 推进地址；变体把右端点计入；
  另一变体省略零交集数据块。不能只把 S02 的端点符号改回去作为全部修复。

### C03 / bounds：裁剪后的加权区间负载

接口：`weighted_load(lower, upper, intervals)`。

`lower <= upper`，域宽 `upper-lower` 为 0..32；区间为
`[start,end,weight]`，start/end 在通用整数范围内且 start<=end，
weight 为 -32..32。返回 lower 到 upper-1 每个整数位置的总权重；
仅 `start <= position < end` 的区间贡献权重。允许空域、空区间、
零权重、负权重和重复区间，区间可完全或部分位于域外。

- P01：参数 `[0,4,[[-1,2,2],[2,5,-1],[1,3,3]]]`，
  期望 `[2,5,2,-1]`。位置 2 不再获得第一段权重，但获得后两段权重。
- P02：参数 `[2,2,[[0,4,3]]]`，期望 `[]`。
- H01–H06：无区间；完全在域外；负下界和两侧裁剪；零长度/零权重；
  重复区间叠加；负权重与相接端点共同作用。
- 参考分解：裁剪后差分再前缀求和；对每个域内整数枚举所有原区间。
- 缺陷目标：初始程序丢弃部分越界区间而非裁剪；变体含右端点；
  另一变体将负权重截为零。

### C04 / reset：交错事务的局部状态

接口：`transaction_totals(events)`。

事件为 `[operation, transaction, amount]`。operation 只能为
`begin/add/commit/rollback`；只有 add 的 amount 为 -32..32，
其余操作的 amount 必须为零。begin 仅用于当前不活跃的 ID；
其他操作仅用于活跃 ID。begin 以零总额开启事务，add 累加，
commit 输出 `[transaction,total]` 并终止，rollback 无输出并终止。
不同 ID 可以交错，终止后可重用 ID；输入末尾未终止的事务不输出。

- P01：参数 `[[["begin","a",0],["begin","b",0],["add","a",5],
  ["add","b",2],["rollback","a",0],["begin","a",0],
  ["commit","a",0],["commit","b",0]]]`，期望 `[["a",0],["b",2]]`。
  回滚 a 不清空 b，新 a 不继承旧金额。
- P02：参数 `[[["begin","a",0],["add","a",-3]]]`，期望 `[]`。
- H01–H06：空事件；负金额提交；提交后重用；回滚后重用；
  三事务交错；同一 ID 多次提交与另一个未结束事务并存。
- 参考分解：按 ID 维护活跃总额；为每次 begin 切分生命周期，
  单独汇总该生命周期的 add，再按 commit 位置输出。
- 缺陷目标：初始程序复用旧 ID 总额；变体任一事务结束时清空全部；
  另一变体将 rollback 当作 commit 输出。

### C05 / reset：按键序列号缺口

接口：`sequence_gaps(events)`。

事件为 `["seq",key,number]` 或 `["reset",key,0]`，number 为 0..1000。
每个键独立保存已接收的最大序列号。首次 seq 的缺口为零；
新 number 大于已保存值时，输出二者差减一并更新保存值；
重复或较旧 number 输出零且不降低保存值。reset 输出零并删除该键状态，
即使键此前不存在。返回每个事件对应的缺失数量，不输出阈值化告警。

- P01：参数 `[[["seq","a",1],["seq","b",5],["seq","a",4],
  ["seq","a",4],["seq","a",2],["reset","a",0],["seq","a",9],
  ["seq","b",7]]]`，期望 `[0,0,2,0,0,0,0,1]`。
  重复/旧序号不后退，重连后的 a=9 不继承旧缺口，b 不受影响。
- P02：参数 `[[["reset","a",0],["seq","a",0]]]`，期望 `[0,0]`。
- H01–H06：空事件；恰好连续；最大跳跃；旧序号之后再前进；
  一键重置但另一键持续；多次重置与重复值并存。
- 参考分解：高水位状态机；对每个 seq 重新查看该键最近 reset 之后的
  先前 seq 最大值。两者不能共用状态更新助手。
- 缺陷目标：初始程序 reset 不清高水位；变体混用各键高水位；
  另一变体让旧序号降低高水位。

### C06 / reset：组内重置与整组峰值

接口：`group_peaks(tokens)`。

tokens 为整数列表，-1000 是结束当前组的标记，-999 是组内重置标记，
其余 -998..1000 是数据值。每组当前和从零开始，每读一个数据值相加，
记录本组所有数据位置上的当前和的最大值。重置只把当前和置零，
不删除本组已见峰值。结束组时输出峰值并清空两层状态。
没有数据位置的组输出 null；不把初始零当数据位置，故峰值可以为负。
流末尾始终输出最后一组，包括空组；空输入返回 `[null]`。

- P01：参数 `[[-3,2,-999,-2,-1000,-2]]`，期望 `[-1,-2]`。
  首组数据位置的当前和为 -3、-1、重置后的 -2，峰值仍是 -1；
  第二组只有 -2。错误地在内部重置时清峰值会得到 `[-2,-2]`，
  因而公开反馈能揭示预定的初始缺陷。
- P02：参数 `[[-1000,-999]]`，期望 `[null,null]`。
- H01–H06：空输入；全部为负；峰值后组内重置并出现较小值；
  连续结束标记；数据后末尾结束标记；两组各有多次内部重置。
- 参考分解：同时维护当前和/峰值/是否见数据；先按组和重置标记切段，
  枚举各段数据位置的前缀和后对整组取最大值。
- 缺陷目标：初始程序内部重置同时清峰值；变体跨组继承峰值；
  另一变体将零当作所有组的最小峰值。

### C07 / multiplicity：库存不足整单拒绝

接口：`fulfill_orders(stock, orders)`。

stock 是标签列表，每次出现代表一张券；orders 是标签列表的列表，
所有订单需求条目之和不超过 32。顺序处理订单；
只有当前库存能同时满足本单所有出现次数时才返回 true 并扣减整单。
否则 false 且库存完全不变。空订单返回 true 且不消耗库存。

- P01：参数 `[["a","a","b"],[["a","b","b"],["a","a"],["b"],[]]]`，
  期望 `[false,true,true,true]`。首单缺第二张 b，不能提前消耗 a/b。
- P02：参数 `[[],[[],["a"]]]`，期望 `[true,false]`。
- H01–H06：没有订单；重复需求恰好满足；所有标签存在但重数不足；
  拒绝后下一单成功；先接受再因耗尽拒绝；两次拒绝后空单和有效单。
- 参考分解：整单频次检查后提交扣减；在独立库存副本逐券删除，
  全部成功才用该副本替换原库存。
- 缺陷目标：初始程序拒绝前已部分扣减；变体按标签存在性检查；
  另一变体成功订单不消耗库存。必须有后续订单揭示事务回滚缺陷，
  不能退化为 S06 的单词库存检查。

### C08 / multiplicity：跨来源的出现票数

接口：`source_quorum(sources, minimum)`。

sources 是标签列表的列表，所有来源的标签条目总数不超过 32；
minimum 为 1..32，可大于来源数量。一个标签在同一来源重复多少次，
都只记一个来源票。返回至少出现在 minimum 个来源中的标签，
按 ASCII 升序，每个标签一次。空来源仍是一个来源，但不投票。

- P01：参数 `[[["b","b","a","d","d"],["b","c"],["a","a"]],2]`，
  期望 `["a","b"]`；a/b 各出现在两个来源，c/d 各仅一个。
  错误地按出现次数而非来源计票会额外返回 d，揭示预定的初始缺陷。
- P02：参数 `[[],1]`，期望 `[]`。
- H01–H06：单来源大量重复仍不足两票；等于门槛；门槛大于来源数；
  含空来源；三个来源各含重复；标签输入顺序不同于 ASCII 顺序。
- 参考分解：每来源去重后累加；对标签全集逐个计算包含它的来源数量。
- 缺陷目标：初始程序把同来源重复当多票；变体全局去重后只计一票；
  另一变体将达到门槛错误写成严格超过门槛。

### C09 / multiplicity：排除同来源的重复值连接

接口：`cross_source_matches(left, right)`。

两侧记录均为 `[value,source]`，value 在通用整数范围内。
返回所有左侧索引与右侧索引构成的配对数量，其中 value 相等但 source
不同。重复记录代表不同索引，必须逐个计数；左右配对有方向，
不是单侧无序组合。空任一侧则为零。

- P01：参数 `[[[7,"a"],[7,"a"],[7,"b"]],
  [[7,"a"],[7,"b"],[7,"b"],[8,"c"]]]`，期望 `5`：
  两条左 a 各匹配两条右 b，加一条左 b 匹配一条右 a。
- P02：参数 `[[[1,"a"]],[[1,"a"]]]`，期望 `0`。
- H01–H06：两侧均空；一侧空；全为不同值；负值重复；
  同值全为相同来源；三个来源且两侧重复次数不等。
- 参考分解：双层枚举索引；按 value 计算两侧总频次乘积，再减去
  同 value/source 的频次乘积之和。
- 缺陷目标：初始程序将每侧记录去重；变体不排除相同来源；
  另一变体对频次取较小值而非乘积。

### C10 / order：最近使用列表的淘汰过程

接口：`recency_evictions(capacity, updates)`。

这是对上位草案“只返回最终键序列”的具体修订建议：同时返回逐步淘汰记录，
避免只比较最后一次出现顺序而与旧顺序题过近。不是新增第十三题。

capacity 为 0..32；updates 为 `[key,value]` 列表，value 在通用整数范围内。
每次更新将已存在 key 从原位置移走，或加入新 key，然后放到最新端；
若超容量，从最旧端淘汰一个 key。更新已有 key 不产生副本。
返回固定字段记录 `{"evicted": [...], "keys": [...]}`：
evicted 逐更新记录淘汰 key，没有淘汰则 null；keys 为最终最旧到最新顺序。
capacity=0 时每次新放入的 key 立即被淘汰；value 不影响键顺序或返回值。

- P01：参数 `[2,[["a",1],["b",2],["a",3],["c",4]]]`，
  期望 `{"evicted":[null,null,null,"b"],"keys":["a","c"]}`。
  更新 a 必须先移到最新端，下一次放入 c 才应淘汰 b。
- P02：参数 `[0,[["a",1]]]`，
  期望 `{"evicted":["a"],"keys":[]}`。
- H01–H06：空更新；容量一反复更新同键；未达容量；淘汰后重新插入；
  三键交错多次淘汰；同值不同键与同键不同值。
- 参考分解：维护有序键列表；维护驻留键的最后访问序号，每次用最小序号
  找淘汰对象。均须输出过程，而非仅对所有更新做末次去重。
- 缺陷目标：初始程序已有键原地更新不移到最新端；变体保留键副本；
  另一变体淘汰最新键。结构审阅须核对实际修复，而不只比较函数名。

### C11 / order：有效投票与稳定并列

接口：`rank_votes(sources)`。

sources 是来源列表，每个来源为 `[candidate,valid]` 记录列表，
valid 是布尔值，所有投票记录总数不超过 32。按来源次序、来源内次序阅读。
每条有效票计一票，包括同来源的重复有效票；无效票既不计数，
也不占首次有效出现位置。输出至少获一票的候选标签，
按票数降序，同票数按首次有效出现次序。来源不赋权也不去重。

- P01：参数 `[[[["b",false],["a",true],["b",true]],
  [["b",true],["a",true]]]]`，期望 `["a","b"]`。
  两者各两票，但 a 的第一张有效票更早。
- P02：参数 `[[[["a",false]]]]`，期望 `[]`。
- H01–H06：无来源；来源均空；一个来源重复有效票；票数不同；
  三候选同票但字典序相反；无效票/重复票/跨来源并列共同作用。
- 参考分解：单遍累计票数及首次有效位置；展平有效票后，逐候选重新
  计数与查找首次位置，再排序。
- 缺陷目标：初始程序无效票占首次位置；变体每来源每候选只记一票；
  另一变体按标签而非首次有效位置破同分。

### C12 / order：分类配额与输出次序

接口：`quota_selection(records, quotas)`。

records 为 `[label,category,priority]` 列表，label 可重复，
priority 在通用整数范围内，越小优先级越高。quotas 为
`[category,limit]` 列表，category 不重复，limit 为 0..32，
未列出的类别额度为零。先按 priority 升序、同 priority 按原索引升序
考虑记录；未用完所属类别额度才选入。最后返回选中记录的原索引，
按原索引升序，而不是按选择次序，也不按 label 去重。

- P01：参数 `[[["x","a",2],["y","b",0],["z","a",1],["w","b",0]],
  [["a",1],["b",1]]]`，期望 `[1,2]`。
  b 的同优先级选较早的索引 1；a 选择更优的索引 2 而非 0。
- P02：参数 `[[["x","a",0]],[]]`，期望 `[]`。
- H01–H06：空记录；零额度；负优先级；同类并列与额度耗尽；
  不同类别相同 label；选择顺序与最终输出顺序相反。
- 参考分解：全局排序后依类消耗额度；每类独立取排序前 limit 项，
  合并原索引后排序。第二份不调用第一份的选择循环。
- 缺陷目标：初始程序按输入次序消耗额度；变体按选择次序返回；
  另一变体按 label 去重而非保留记录身份。

## 4. 结构审阅不是“换个名字”

结构审核先比较题意与最小所需修复，再允许写可执行题库。初始程序和错误
变体落地后还须再查一次：复杂的正确程序可能掩盖一个过于简单的初始缺陷。

重点近邻：

| 对象 | 接近之处 | 必须体现的不同约束 |
| --- | --- | --- |
| C01 / C07 | 顺序资源准入 | 时间过期释放与库存多重需求/整单回滚分别有不可省略的见证 |
| C04 / C05 | 按键状态 | 显式事务开始/提交/回滚与乱序序号高水位/重连分别验证 |
| C02 / S02 | 半开区间交集 | 控制段不占地址与输出位置保留必须成为实际修复部分 |
| C06 / S03 | 分段累积 | 内层清当前和但保留峰值，外层同时清空；负峰值不能被零掩盖 |
| C07 / S06 | 多重库存 | 失败原子性必须通过后续订单暴露，不是单次补一个 remove |
| C08 / C11 | 多来源计票 | 前者同源去重，后者每张有效票都计数且有首次有效位置 |
| C09 / S05 | 重数计算 | 跨侧乘积与同源扣除，不是袋交集的最小频次 |
| C10 / 旧末次顺序题 | 最近出现顺序 | 逐步淘汰及重插入见证，而非只输出末次去重 |
| C12 / S07 | 排序与并列 | 分类限额、原索引身份、选择顺序与输出顺序分离 |

这张表不是完整去重通过结论。后续逐项记录 12×8=96 个新题/监督关系、
12×4=48 个新题/旧开发关系以及 12×11/2=66 个新题内部关系。
旧设计中已公开的结构信息可用于标注近邻，不读取旧迁移/保留评分答案或
模型结果来挑新题。旧题不再作为新方案独立验证集。
不同家族标签、不同函数名或多一层输出包装都不能自动判为不同结构。

## 5. 参考答案与反例如何核验

每题后续材料包含：

1. 完整题面、入口签名、合法输入域和 P01/P02。
2. H01–H06 的精确输入、完整期望值和逐步手工推导；一例可覆盖多个约束，
   但六例输入均须不同于公开例及彼此。
3. 两份不同分解的参考实现，沿用第 3 节分别指定的方法。第二实现的作者
   先只看规格/用例，不以第一份源码为模板；提交后再交叉核对。
4. 一份初始错误实现与至少两份行为不同的错误变体。初始程序至少被一条
   公开用例拒绝；三种错误源码各有具名见证和手工预测的错误结果。
5. 静态语法/入口/输入域检查，以及不同审阅者的逐例答案复核。
   第二 agent 不是独立人工签核，继续标为助手构建的受限开发材料。

每题五份源码乘八个用例，计划至少 12×5×8=480 个固定源码核验位置；
这是未来动态数据检查规模，不是已经执行，也不并入模型的 624 次执行上限。
不得在宿主直接 import/exec 题库源码。动态核验须有另行审阅的隔离执行方案；
静态阅读/AST 解析不冒充动态通过。

动态检查必须显示两份参考实现各自八例通过，以及每个错误源码在指定见证
被拒绝；不能只汇报“至少发现一个错误”。参考分歧、手算分歧或 oracle 错误
阻止整版冻结，修订记录要保留。不能把有疑问的答案反馈给待测模型。

## 6. 分层文件与防泄漏

后续本地数据实施使用独立目录 `experiments/lora_necessity/data/recalibration_v2/`，
不覆盖已有 v1 文件。下列是拟议文件，不表示现在已存在：

- `structure.json`：12 个 ID、机制、签名、修复要求与结构审阅记录。
- `prompts.json`：只含题面、入口、初始程序、公开输入/期望值。
- `oracles.json`：公开用例绑定、私有输入/期望值、两参考实现与两错误变体、
  逐例推导和见证；只交受信评分/核验端，不给生成端或候选读取。
- `review.md`：静态审查、重叠判定、人工/agent 身份、未验证项。
- `manifest.json`：身份/字节摘要及静态、动态、长度三个独立状态，
  未完成状态为 pending，不借用旧 v1 的 pass。

八个监督示例继续只引用原始 `data/supervision_v1.json`，
不混入 C01–C12 的答案。真实提示渲染必须只投影允许字段；不能依赖
“同一大 JSON 里有答案但提示暂时没用”来建立运行隔离。
本文件含公开例与答案方法，也不能作为待测模型的完整提示。

未来组件分开实施：数据静态验证、v2 分叉身份/排程、生成端投影、
三候选评分与五状态统计。旧四题两轮 driver 不支持 v2，不能只改题目数。
长度核验仍针对真实 tokenizer：4096 输入、256 输出，包括原八例、
完整首轮候选与反馈/无结果续答；不得按字符数猜测可执行性或静默截断。

## 7. 判定规则与收尾门槛

沿用上位设计，不增加“feedback 必须胜过 retry”的准入要求：

- 固定计划为 72 次生成、最多 48 次公开执行、576 个最终评分位置，
  合计最多 624 次候选执行；本阶段实际模型调用为零。
- 五状态保持 PASS/SEMANTIC_FAIL/EXECUTION_FAIL/UNKNOWN/INVALID_EVIDENCE。
  未知不是确认失败，格式拒绝的零执行不是八份丢失回执。
- 有完整证据的候选级错误照常继续后续计划，不自动补跑；
  身份/隔离/基础设施/必要证据不完整则中止，保留未完成位置。
- 机会校准拟沿用：每种记忆首轮至少三对、三条完整正常的语义错误；
  至少两个错误被公开用例揭示，并覆盖至少两个机制。
  这只是待运行的工程预警条件，不是统计功效或必能满足的承诺。
- 反馈零收益、负收益、最终全对均报告。校准再次不足就接受不足，
  不无限换题；不凭正反馈诊断自动训练 LoRA。

进入可执行数据编写前，应审阅本文件的具体定义，特别是 C05 的缺口数量、
C06 的空组/负峰值，以及 C10 新增淘汰过程输出。随后只进入数据和静态审查；
模型/分词器、动态源码核验和远程运行仍不随之自动启动。
训练与 LoRA 对照需要新的未参与设计的迁移/保留材料及明确效果/退化门槛。

本阶段无 UI 可视化问题；目的、比较路线与不运行边界已由前述对话明确。
书面规格审阅前不编写执行代码或实施计划，不提交/推送。
