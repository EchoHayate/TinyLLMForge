## 1. 目标与范围

为一次受信 CPU tokenizer 审计提供可验证的聚合资源限制、有界文件存储、
独占归属、断连后到期停止和完整清理。不构建通用调度平台，不处理不可信
候选程序，不增加模型生成、LoRA 训练、GPU 使用或科学效果结论。

继承 `docs/superpowers/specs/2026-11-12-lora-tokenizer-admission-design.md`。
本文件只澄清该规格第 7 节的资源后端实现边界，不修改原文件及历史封存。
指定 tokenizer、数据字节、324 行审计清单、停止规则和私有传输关口不变。
父规格中的历史实施状态不用于重新打开后来已验收的本地组件。

首选路线是已有 Docker 服务上的专属任务，配合不依赖客户端存活的远端
生命周期控制。若无法在同一目标上满足本规格，输出明确缺项并请求平台支持；
不得悄悄换主机、放宽预算或退化为普通进程加轮询。

## 3. 不变的预算

| 项目 | 要求 |
| --- | --- |
| 聚合内存 | 4 GiB = 4,294,967,296 字节 |
| 并发任务 | 合计至多 8 个进程/线程任务 |
| 新任务文件 | 峰值合计占用不超过 128 MiB = 134,217,728 字节 |
| 结果 | 至多 64 MiB = 67,108,864 字节 |
| stdout / stderr | 各至多 1 MiB = 1,048,576 字节 |
| 工作窗 | 初次连接起至多 540 秒 |
| 总窗 | 同一起点至多 600 秒 |
| 清理窗 | 开始清理后至多 60 秒，且不超过原总窗 |
| 其他 | 单线程配置、禁用 core dump、一次连接、一次审计、不自动重试 |

用户已确认 128 MiB 按“任意时刻合计占用”计，不是累计写入字节。
删除并实际释放的空间可复用；删除路径本身不证明占用已经释放。
这项解释只用于后续验收，不追溯改写旧结果。

## 4. 组件、归属与数据流

### 控制端

冻结本次 run ID、输入清单、授权范围和已审阅 profile；通过单次安全连接
接收有界结果，验证原始字节和证据，不因远端返回 PASS 字符串而放行。
已有 `LaunchWindow` 继续负责本地时间记账，不声称它终止了远端任务。
已有 `OwnedChild` 仅负责其直接子进程，不扩展成任务树清理证明。

### 远端生命周期控制

持有准确任务对象的控制权，准备资源域、验证部署配置、监督期限并清理。
生命周期控制不能因为 SSH 断开就丧失到期停止能力，也不能向审计进程
暴露 Docker socket、管理凭据、SSH agent 或复用控制 socket。
新增控制任务自身的资源、文件与退出责任必须列入 profile。

### 受信审计任务

在准入后的资源域中完成快照校验、输入处理、审计和有界输出。
快照与输入在启用其消费者前完成字节绑定；审计只读快照，保持父规格的
依赖与导入限制。传输和生命周期不混入已有中立计数/渲染组件。

顺序固定为：绑定范围 → 资源域及期限就绪 → 准备并核对输入 →
执行已获准工作 → 接收并校验结果 → 终止及释放核验 → 封存结论。
准备和采集阶段不能游离在已宣称的限制之外。

## 5. 真实 profile 必须先于启动器定型

profile 是“选择器＋原始观察＋审阅决定”，不是任意调用者填写的
`limits_enforced=true`。每一项至少绑定观察时间、目标身份、原始证据摘要
及适用的配置/对象；无法观察的项明确缺失，不以默认值代替。

| 分类 | 冻结所需信息 | 缺失时的结论 |
| --- | --- | --- |
| runtime | 已存在且可使用的镜像准确 ID/摘要、架构、入口、用户、volume 声明、依赖清单 | `PROFILE_INCOMPLETE` |
| 解释器 | Python 3.12.13、transformers 4.57.1，父规格要求的其余精确依赖 | `IDENTITY_NOT_ADMITTED` |
| 资源归属 | 审计、准备、采集、生命周期控制各自归属及总预算证明 | `PROFILE_INCOMPLETE` |
| 存储 | 全部写路径、空间域、硬限额、只读路径、父目录归属与计量单位 | `PROFILE_INCOMPLETE` |
| 期限 | 远端控制机制、断连行为、时间映射、清理余量及可控制对象 | `PROFILE_INCOMPLETE` |
| 授权 | 镜像/控制接口使用范围、任务创建/删除范围和无外部影响边界 | `AUTHORIZATION_MISSING` |

镜像 tag 不能替代准确身份。没有现成合格镜像时停止，不自动 pull/build、
挂载旧虚拟环境或借用其他工作负载。父规格的 Python/依赖约束不能因为
换用容器而消失。元数据读取不等于已启动解释器或验证依赖可导入。

第一份实施计划只完成这个 profile 的调查与审阅，不创建另一个纯声明式
准入类，也不先实现依赖未知 runtime 的启动器。

## 6. 资源与存储证明

### 聚合资源

列出所有本次远端准备、审计、采集和控制辅助任务的资源组。
若一个共同资源域不能覆盖全部任务，必须证明独立硬限额之和不超总预算，
并证明任务不能逃出这些资源域。不能给每个容器各配 4 GiB/8 任务，
再宣称本次任务合计仍为 4 GiB/8 任务。

既有平台 daemon/SSH 服务与新增任务的边界要显式列出；
不能假设单容器参数限制了宿主控制程序。无法为新增辅助任务提供边界时
不准入。容器内 init、线程及辅助子进程均计数，不只统计 Python 主进程。
内存限制必须包含适用的 tmpfs 占用；不使用 swap 扩充任务预算。

### 文件占用

为本次新生成或复制的文件列全空间域：快照、输入、结果、日志、临时文件、
辅助挂载及控制端接收文件。跨主机副本也是不同实际占用，不能按内容摘要
相同只算一次，也不能默认远端和本地各获得完整 128 MiB。
既有源数据与只读运行环境不是本次新写入；新副本必须计入。

每个独立空间域的硬限额及必要固定占用之和不得超过 134,217,728 字节。
若设计采用跨阶段复用，必须先有实际释放证据，再转移额度。
稀疏文件的逻辑长度不替代实际分配计量，反之也不能用稀疏文件绕过
结果/日志的逻辑字节限制。已删除但仍打开的文件仍按后端实际占用计。

tmpfs/文件系统配额是候选机制而非验收结论；明确其数据块、元数据和 inode
计量边界。未被文件空间限额覆盖的内存开销必须受聚合内存约束，并在
profile 中说明，不能声称 128 MiB 包括所有内核内存。
所有可写挂载须禁止写入或有预算，不能漏掉 `/dev/shm`、镜像隐式 volume、
runtime 临时目录和额外输出副本。未覆盖的任务输出路径直接拒绝。

结果、stdout、stderr 在产生和接收两端实施有界协议；
只在接收端截断并不证明远端写入受限。协议溢出停止工作并保留失败原因。
容器日志驱动不得无界另存任务输出；宿主平台既有日志不读取、不修改，
但不得把私有内容放入命令行或平台日志，也不得声称平台日志受任务配额管理。

## 7. 到期停止与失败处理

唯一的本地时间起点来自既有 `LaunchWindow.claim_connection()`。
从连接、资源准备到工作开始均消耗同一时间窗，远端不能重新获得整段 600 秒。
远端资源和生命周期机制未就绪之前，不允许向审计任务发出工作许可。

跨机 monotonic 数值不得直接比较。实现必须给出保守的期限握手、
往返延迟/计时误差处理及失效规则，并在实际 runtime 上验证。
时钟异常、迟到的工作许可、旧 nonce 或超期消息一律拒绝；
没有可证明的保守映射则不启动，不能假装两个时钟共享纪元。
本规格不凭空指定一个未经支持的漂移容差。

故障路径至少覆盖连接中断、控制端退出、输出溢出、资源拒绝、OOM、
任务无响应、控制接口异常、时钟异常和结果校验失败。
先停止接收新工作，按剩余清理窗终止并回收本次对象；
控制端不能为了补拿报告而重连或延长预算。

控制对象绑定 run ID、创建回执、准确容器/资源域身份及私有根身份；
禁止按通用名字、进程名或全机扫描批量清理。对象身份不符时不得误杀、
误删，保留 `CLEANUP_UNVERIFIED` 并请求人工处理。
API 创建响应丢失必须有按本次专属身份核对的方案，不能再次创建赌重试成功。

正常路径在易失存储释放前回收结果；超时或断连时允许无法取得完整结果。
完整清理要求分别证明任务及后代已结束、资源域释放、传输端点关闭、
本次临时根已释放或已按批准的证据保留策略处理。
发送终止信号、收到命令 exit 0 或看不到容器名字都不是单独的充分证据。
总窗到期仍无法证明完整释放时封存失败，不重试，不改写为成功。

## 8. 验收矩阵

| 编号 | 要证明的边界 | 最低证据 | 必须拒绝的情况 |
| --- | --- | --- | --- |
| B01 | 精确 runtime | 镜像及配置绑定、版本原始观察、审阅 profile | tag 漂移、缺依赖、偷偷下载 |
| B02 | 内存合计 | 组归属、实际限值、小型受控行为、最终配置核验 | 只限制一个子进程或未覆盖辅助任务 |
| B03 | 8 个任务 | init/线程/子进程归属及有限创建被拒绝的证据 | 用进程数冒充进程＋线程数 |
| B04 | 峰值 128 MiB | 全路径和副本预算、实际空间限制、跨目录行为 | 多个挂载分别获得 128 MiB |
| B05 | 单项输出 | 产生/传输/接收端边界及超限停止 | 截断后仍宣称完整报告 |
| B06 | 全窗与断连 | 同一预算映射、超期拒绝、断连后的停止观察 | 用 stop grace 当总运行时限 |
| B07 | 独占清理 | 创建身份、后代/端点/空间的独立释放证据 | 重用名字、越权杀任务或删目录 |
| B08 | 受信输入 | 原字节及行序绑定、快照只读、私有投影单独授权 | 用公开输入许可传私有答案 |
| B09 | 停止语义 | 缺失/溢出/时钟/API 失败时完整的失败分母 | 重试、放大预算、跳过失败行 |
| B10 | 保全 | 原数据及组件证据哈希、精确新增文件范围 | 覆盖旧封存或修改预期值放行 |

行为探针只用固定、有限的无模型工作，不用无界 fork/内存耗尽验证未知限制。
探针外层边界必须先被确认；小限额试验不能冒充最终资源配置实测。
最终配置须重新绑定实际限值、归属和已验证的同一机制，
“达到极限”探针是否安全及是否需要平台保障由独立行为测试范围决定。

## 9. 实施分段与结论

1. **真实 profile 调查与审阅**：运行环境、控制权限、空间与期限方案。
   当前计划为 `docs/superpowers/plans/2026-11-13-lora-tokenizer-backend-profile.md`。
2. **启动器与生命周期实现**：只有 profile 完整并获认可后才写该段的精确代码计划；
   沿用已验收接口，不为未知平台接口编造实现。
3. **独立有界行为验证**：范围和代码审阅获准后执行，失败封存。
4. **真实 tokenizer 审计**：父规格要求的身份、输入、私有传输再单独准入。

后端行为验证通过的类型只能是
`BACKEND_BEHAVIOR_VERIFIED_NOT_TOKENIZER_ADMITTED`。
profile 调查的类型只能是 `BACKEND_PROFILE_REVIEWED_NOT_ENFORCED`
或带具体缺项的未就绪结论，不能设置 enforcement 为 true。
`benchmark_eligible`、`formal_evaluation_ready`、`net_benefit_established`、
`isolated` 和 `all_possible_second_rounds_validated` 始终 false。
当前 `resource_limits_enforced`、`cleanup_verified`、`real_tokenizer_loaded`
也均为 false；本规格完成不等于任一实现或实验完成。
